# UFSP2.0 业务页面组件与模板盘点

> 状态：第一轮代码事实盘点。用于决定哪些内容直接复用、哪些需要组件化、哪些只保留为历史参考。本文不替代 `业务页面设计规范.md`，也不把仍待确认的提示词管理页面作为视觉基线。

## 1. 盘点结论

当前项目已经形成较稳定的业务页面设计语言，但“规范、主题、组件、页面模板”尚未完全闭环。

最关键的事实：

- `TopBar` 已是真正的公共组件，当前被 17 个原型入口复用。
- 系统功能菜单、业务树、按钮、输入框、查询工具栏、表格、分页、表单页头虽然已有稳定样式和统一的 `ufsp-*` 命名，但主要仍复制在页面 CSS 中。
- 考评页、提示词页等通过导入问题库 CSS 继承部分基础样式，再叠加自己的 CSS；这种方式容易在需求调整时产生覆盖、回退和局部漂移。
- `src/themes/antd-new` 仍是通用 Ant Design 主题，不是完整的 UFSP2.0 业务主题。
- `src/components/side-menu`、`src/components/ref-button` 属于旧通用示例，部分尺寸与当前业务基线冲突，不能直接作为新页面组件来源。

因此，之前反复出现“需求变了，已确认样式也被改掉”的根本原因不是规范文字不够多，而是大多数标准还没有成为唯一公共实现。

## 2. 当前资产分类

### 2.1 可直接保留

| 资产 | 当前状态 | 处理 |
| --- | --- | --- |
| `src/common/components/TopBar.tsx` | 已被 17 个原型复用 | 继续作为唯一公共顶部导航 |
| 问题库、案例库已确认页面 | 强基准 / 局部基准 | 提取结构、组件和状态，不整页复制 |
| 问题库、案例库专业 SVG / iconfont | 已确认图标来源 | 按业务语义复用，避免同类页面混用图标库 |
| `src/docs/业务页面设计规范.md` | 当前业务视觉口径 | 作为主题、组件和模板的设计依据 |

### 2.2 已稳定但尚未公共化

| 类别 | 当前主要位置 | 风险 |
| --- | --- | --- |
| 系统功能菜单 | 问题库、案例库页面 CSS / JSX | 多页重复，折叠、图标和选中态容易漂移 |
| 业务树 | 问题库、案例库页面 CSS / JSX | 宽度、搜索、节点状态和折叠把手仍由页面维护 |
| 按钮与图标按钮 | 多个页面的 `.ufsp-btn*` | 同名 class 分散定义，页面覆盖可能改变全局观感 |
| 输入框与搜索框 | `.ufsp-search-box` 及页面表单 class | 聚焦态、边界和字号容易被局部选择器覆盖 |
| 查询工具栏 | 问题库、案例库页面 | 结构已稳定，但仍靠复制 JSX 保持一致 |
| 表格与分页 | 问题库、案例库页面 | 样式基本一致，但冻结列、滚动和分页仍可能分别修复 |
| 全页面表单页头 | `.ufsp-form-head` 等页面 class | 多页使用，尚无统一组件契约 |

### 2.3 不能作为当前业务基线

| 资产 | 冲突 | 处理 |
| --- | --- | --- |
| `src/components/ref-button` | 40px 按钮、6-8px 圆角，与当前 32px / 4px 业务控件不一致 | 标记为旧示例，不参与新业务页 |
| `src/components/side-menu` | 240px 展开宽度、48px 标题区，与当前业务页 272px 菜单及标题结构不一致 | 仅保留数据接口参考，不复用视觉实现 |
| `src/themes/antd-new` | 主色、圆角、画布等仍是通用 Ant Design 默认口径 | 保留通用基础，只从中继承相符项 |
| `prompt-version-management-v1` | 业务方案和页面仍在校准 | 只用于理解提示词业务，不用于提取视觉组件 |

## 3. 已发现的实现缺口

### 3.1 主题变量未形成唯一来源

当前通用主题与实际业务页存在差异：

- 主题默认主色为 `#1677FF`，业务页主操作普遍使用 `#1890FF`。
- 主题默认圆角为 `6px`，业务控件确认口径为 `4px`。
- 主题画布为通用灰色，业务页使用浅灰蓝 `#F5F8FF / #F8FAFC`。
- 表头蓝灰、系统菜单品牌蓝、业务树选中色等尚未成为统一语义 token。

结论：不能只修改通用 Ant Design token；需要补一层 UFSP2.0 业务语义变量。

### 3.2 同名样式不等于公共组件

`.ufsp-btn`、`.ufsp-search-box`、`.ufsp-form-head` 等命名已经稳定，但定义仍存在于不同页面 CSS。只要页面增加更具体的选择器，就可能覆盖既有标准。

结论：后续应把高频样式迁移为公共组件或公共样式入口，页面只保留业务布局和特有字段样式。

### 3.3 页面高度仍有不一致

- 公共 `TopBar` 实际高度为 `64px`。
- 问题库主工作区仍使用 `calc(100vh - 56px)`。
- 案例库主框架使用固定 `920px` 高度。

结论：视觉样板需要先统一 1920×1080 下的页面高度计算；确认后再决定同步哪些旧页面，不在本轮盘点中直接覆盖。

## 4. 建议组件化清单

### 第一批：基础与高频

1. UFSP2.0 业务语义 token。
2. `Button / IconButton`。
3. `Input / SearchBox`。
4. `FeatureSidebar` 系统功能菜单。
5. `FormHeader` 全页面表单页头。

### 第二批：列表页组合

1. `BusinessTree`。
2. `ListTabs`。
3. `ListToolbar`。
4. `DataTable`。
5. `Pagination`。

### 第三批：页面模板

1. 无树列表页。
2. 有树列表页。
3. 状态页签 + 业务树 + 列表页。
4. 全页面新增 / 编辑表单。
5. 详情 / 审核 / 处理工作区。
6. 首页 / 工作台共同设计语言模板。

## 5. 批量确认方式

后续不逐个确认参数，采用以下方式：

1. 使用现有强基准自动生成视觉样板。
2. 样板集中展示完整页面骨架、按钮层级、输入状态、系统菜单、业务树、工具栏、表格、分页和表单页头。
3. 用户只指出不正确的位置；未指出部分视为本轮通过。
4. 通过后再抽取公共组件和页面模板。
5. 只有强基准冲突、新组件、新变体或跨页面覆盖时单独询问。

## 6. 下一步

下一步先制作可运行的视觉基线样板，不立即重构现有业务页面。样板确认后，再按“主题变量 → 公共组件 → 页面模板”的顺序实施，避免边确认边改多个旧页面。
