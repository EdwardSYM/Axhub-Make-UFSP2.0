## 1. 规范目标

本规范用于后续新增业务操作页时，直接复用 UFSP2.0 已确认的页面骨架、组件比例和交互习惯。旧 RP/Axure 原型用于补充页面范式和业务语义，不直接作为最终视觉标准。

后续 Codex 生成业务页面时应遵守：

- 完整业务页面按“公共 TopBar → 系统功能菜单 → 业务核心区”组织；业务核心区按需求再使用“业务树/目录 → 列表”结构。
- 公共 TopBar 和已确认系统功能菜单只复用，不重新设计。
- 页面结构优先复用当前项目 React/Tailwind/Ant Design 组件能力。
- 视觉结果以当前已确认页面为准：浅灰蓝外部画布、白色业务面板、32px 控件、4px 控件圆角、紧凑表格和明确操作区。
- 数据全部使用本地 mock 数据，不接入后台接口、权限、真实公式和复杂校验。
- 本规范定义为“业务页面规范”，不要和全景分析、工作台、首页等已有页面规范混合。

### 2.1 来源优先级

同一尺寸、样式或结构出现冲突时，按以下顺序判断：

1. 用户本轮明确确认的截图、标注和要求。
2. `rules/confirmed-baselines.md` 中的强基准。
3. 项目中真实复用最多、覆盖页面最广的公共组件或稳定实现。
4. 案例库、问题库、考评库等已确认页面的现有实现和 `spec.md`。
5. 本规范已经固化的共性。
6. Axure HTML 中跨多个模板重复出现的结构。
7. 单个旧业务页面、通用 skill、通用 UI 经验。

“复用最多”只用于同类组件之间的冲突裁决，不能覆盖用户最新明确确认。例如顶部导航以全项目复用的 `src/common/components/TopBar.tsx` 为唯一基准；但如果用户明确更新了 TopBar 规范，应以最新确认结果为准并评估全项目同步。

旧 HTML 中的 `48px` 顶栏、`256px` 左栏、绝对坐标和单页局部样式不得覆盖当前项目的 `64px TopBar`、`272px/64px` 系统功能菜单和响应式 flex/grid 布局。

## 3. 内容区定位

完整业务页面的稳定层级为：

```text
公共 TopBar（64px）
└── 页面工作区（1920 × 1080 为主要设计校准视口）
    ├── 系统功能菜单（展开 272px / 收起 64px）
    └── 业务核心区（自适应）
        ├── 可选：状态页签
        └── 核心内容
            ├── 可选：业务树 / 分类目录
            └── 列表、表单、详情或业务工作区
```

完整页面建议结构：

```tsx
<Page>
  <TopBar />
  <main className="ufsp-page-workspace">
    <FeatureSidebar />
    <section className="ufsp-business-shell">
      <BusinessPage />
    </section>
  </main>
</Page>
```

业务核心区内部建议结构：

```tsx
<section className="ufsp-business-panel">
  <BusinessTabs />
  <div className="ufsp-ledger-content">
    <BusinessTree />
    <BusinessMain />
  </div>
</section>
```

职责边界：

- `TopBar`：全局导航、全局搜索、通知、用户信息。
- `FeatureSidebar`：当前系统/资源库内部功能菜单，必须位于业务树之前。
- `BusinessTree`：只承担当前功能内部的数据分类、筛选和定位，不等同于系统功能菜单。
- `BusinessPage`：列表、表单、详情、业务树、工具栏、分页和业务反馈。

不得用业务树替代系统功能菜单，也不得把两者顺序颠倒。

## 4. 设计原则

### 4.1 基于 Ant Design，但不是默认 Ant Design

项目已明确基于 Ant Design 微调改造。后续实现时：

- Button、Input、Select、DatePicker、Table、Form、Drawer、Modal、Tabs、Pagination、Tree、Upload 等优先按 Ant Design 语义组织。
- 视觉 token 采用 UFSP 业务页提取值，不直接使用 Ant Design 默认蓝、默认边框和默认留白。
- 若使用 Tailwind 静态实现，也应保持 Ant Design 的控件语义、状态和反馈逻辑。

### 4.2 内容区优先级

列表类业务页面的信息层级应按以下顺序组织：

1. 系统功能菜单中的当前功能位置。
2. 状态页签（存在生命周期/办理状态时）。
3. 业务树/目录与列表工作区。
4. 页面级操作和查询工具栏。
5. 表格及行级操作。
6. 分页和必要反馈。

新增、编辑、详情、审核等全页面工作区的信息层级为：

1. 64px 表单页头中的返回、标题和页面级动作。
2. 表单/详情分组。
3. 字段、附件、关联信息。
4. 日志、说明和次要信息。

系统功能菜单已经清楚表达当前位置时，列表页不再重复增加大标题、面包屑卡片或说明块。

### 4.3 密度

原型属于中后台业务系统，信息密度偏紧凑：

- 主要校准视口为 `1920 × 1080`；页面使用自适应高度，不把 Axure 的 `900px` 内容高写死到组件中。
- 公共 TopBar 高度 `64px`。
- 页面工作区外边距和系统菜单/业务面板间距以 `16px` 为主。
- 系统功能菜单展开 `272px`、收起 `64px`，菜单行高 `44px`。
- 控件高度以 `32px` 为主。
- 表格行高以 `32px` 为主。
- 页签栏常用 `48px`，列表工具栏常用 `56px`，表单页头 `64px`。
- 内容面板内边距常用 `16px` 或 `24px`，复杂表单保持 `24px` 起步。

### 4.4 列表页左侧菜单

列表页左侧菜单承担同一业务域内的主导航，不应由各页面各自定义分组、选中和折叠样式。原因是用户会在问题库、案例库等列表页之间连续切换，菜单如果在层级表达、选中反馈和收起密度上不一致，会削弱位置感，并让父级目录误看成另一类控件。

- 菜单最多表达两级：一级节点用于业务分类或直接功能入口，二级节点用于分类下的具体页面；更深层级应下沉到页面内页签或树。
- 一级父级和一级无子菜单节点必须使用同一导航行标准：行高 `44px`、图标槽 `30px`、图标与文字间距 `10px`、左右内边距 `12px`、圆角 `4px`，有子菜单时箭头固定在行尾。
- 二级节点只通过左缩进表达从属，推荐左侧缩进 `24px`，其图标槽、文字字号、行高和悬停态仍与一级节点保持一致。
- 父级展开时，当前分组只作为归属态，可用深蓝文字或轻量图标色提示，但不得加粗、不得使用选中底色；只有当前叶子节点、无下级一级节点，或父级收起后承接当前页位置的父级行可以加粗。
- 列表页菜单配色沿用顶栏深蓝体系：主来源为顶栏渐变 `#2A487E → #4A6FA8`，选中态使用低饱和蓝灰行面、深蓝文字和半透明深蓝图标底，不使用亮蓝、左侧粗状态线、渐变行面、过大的圆角或强投影；悬停态只做轻量蓝灰底和深蓝文字反馈。
- 菜单顶部模块 logo 是身份标识，不是导航项；不得使用边框、浅底图标盒、实心徽章或与菜单项相同的图标槽。推荐只保留顶栏同源深蓝线性图标与标题文字，让菜单项图标槽只出现在真正可选的导航行内。
- 菜单整体折叠为图标模式时，所有节点使用同一 `44px` 图标按钮节奏，图标容器建议 `32px`，不得因是否有子菜单改变垂直间距。
- 菜单整体收起/展开控制放在菜单标题区右侧或折叠态顶部，不放在侧栏底部空白区；按钮采用 `28px` 左右的轻量图标按钮，不使用阴影、边框盒或大面积留白。

### 5.3 间距

采用 4px 网格，业务页常用：

| 值 | 用途 |
| --- | --- |
| `4px` | 图标与文字的最小间隔、小标签内部间距 |
| `8px` | 按钮间距、工具栏控件间距、表单细分组间距 |
| `10px` | 多条提示之间的间距，数据标识提示页使用 |
| `16px` | 主面板内边距、页签内容区内边距、表单项纵向间距 |
| `24px` | 弹窗/抽屉/卡片大内边距 |
| `32px` | 控件高度、图标按钮方形尺寸、表格行高 |
| `48px` | 标题栏、页签栏、卡片标题栏 |
| `64px` | 新增/详情页面顶部标题操作栏 |

### 5.4 圆角

| 场景 | 圆角 |
| --- | --- |
| 输入框、按钮、选择器、表格、树节点 | `4px` |
| 系统功能菜单、业务核心外层面板 | `8px` |
| 复选框 | `2px` |
| 抽屉 | `0px`，如在内容区内做卡片式抽屉可保留 `4px` |
| 专题页中的业务卡片 | `8px`，与业务核心面板一致；同一页面不得混用 `8px / 12px / 16px` |

胶囊搜索框、圆形返回按钮、头像等具有明确形态语义的组件不按业务卡片处理，可保留全圆角；普通内容卡片不得以“更圆润”为由自行放大圆角。

### 5.5 层级、边界与阴影

原型总体采用“信息层级优先、边界克制”的中后台风格。页面层级可通过留白、文字权重、浅底分组、圆角行面、局部分隔和少量表面色差共同表达；不默认给每个区块增加完整描边，也不把删除边界本身当成优化目标。

通用原则：

- 先判断关系，再选择手段：同组信息优先用字重和间距；相邻分组可用浅底、缩进短线或局部分隔；业务阶段切换可用更连续但低对比度的结构线；独立载体和独立操作区域才使用完整边界或表面层级。
- 普通内容分组、摘要区、列表行和说明区不默认做卡片，也不默认完全无边界；以快速识别区块归属和稳定阅读轴线为验收标准。
- 需要明确操作边界、阅读载体或结构定位时应保留弱边界，例如输入控件、表格网格、页签底线、树/列表中线、弹窗/抽屉、文书纸张和聚焦状态。
- 同一层级内不同时叠加完整描边、明显阴影和大面积底色；能用留白或浅底表达时，不再加边框。
- 分隔线应分级：主阶段、阅读列、局部分组在线长、方向、缩进和透明度上有所区别；不把所有线都做成贯穿边框，也不因追求简洁而全部删除。
- 边界克制不等于取消可访问性和操作反馈；输入、聚焦、选中、错误、危险操作仍需有清晰状态。
- 最终用视觉整体判断：快速扫视时应能看出页面主结构和阅读顺序，但不应首先注意到边框、阴影或装饰线。

| 场景 | 规则 |
| --- | --- |
| 主业务面板 | 默认无完整描边、无阴影或极弱阴影，主要靠白底、浅灰蓝外部画布、留白和必要轻分隔线分层 |
| 普通内容分组 / 列表项 | 默认无边框，通过浅底、行距、文字层级和选中态表达；交互悬停可增加轻底色 |
| 普通输入/次级按钮 | `box-shadow: 0 0 2px rgba(0,0,0,.35)` |
| 主按钮/蓝色图标按钮 | `box-shadow: 0 0 2px rgba(24,144,255,.35)` |
| 输入聚焦 | 取消浏览器原生 outline，使用 `box-shadow: 0 0 5px rgba(24,144,255,.28-.35)` |
| 下拉/展开框 | `box-shadow: 0 0 4px rgba(0,0,0,.35)` |
| 抽屉 | `box-shadow: 0 4px 12px rgba(0,0,0,.15)` |
| 弹窗 | `box-shadow: 0 4px 12px rgba(0,0,0,.35-.45)`，实现时建议取更克制的 `.20-.28` |

## 6. 页面框架模板

### 6.1 业务内容画布

旧原型中业务内容区域使用 `#E6F7FF` 画布和 `8px` 内缩。当前确认页面已调整为：

- 页面外部画布：`#F5F8FF` 或 `#F8FAFC`。
- 页面工作区：`16px` 外边距和 `16px` 列间距。
- 系统功能菜单、业务核心面板：白底、`8px` 圆角、极弱阴影。
- 业务核心区内部：以白底、留白和轻分隔线组织，不再强制嵌套整块亮蓝画布。
- `#E6F7FF` 保留为树选中、分隔把手、局部缓冲和轻量反馈色。
- 默认正文字号：`14px`。

当前项目建议结构：

```css
.ufsp-page-workspace {

  padding: 16px;
}

.ufsp-business-shell {
  flex: 1;
  min-width: 0;
  height: 100%;
  min-height: 0;
  background: transparent;
  padding: 0;

  overflow: hidden;
}

.ufsp-business-panel {
  height: 100%;
  background: #fff;
  border-radius: 8px;
  overflow: hidden;

```

业务面板内部的控件、表格、树节点仍以 `4px` 圆角为主；外层面板 `8px` 与内部控件 `4px` 不混用。

### 6.2 主列表页（无树）

适用：普通列表、台账列表、任务列表、案例列表、配置列表。

结构：

```text
业务内容画布
└── 白色主面板
    ├── 工具栏 / 筛选区
    ├── 表格
    └── 分页
```

规范：

- 主面板填满剩余高度，外层圆角 `8px`。
- 工具栏默认高度 `56px`。
- 页面级动作在左，固定查询组件在右。
- 右侧查询默认使用：`240px` 输入框 + 查询 + 刷新 + 筛选 + 查询方案 + 列设置。
- 输入框高度 `32px`，按钮高度 `32px`。
- 表格区域应占主要面积，不要在列表上方堆叠过多卡片。

### 6.3 主列表页（有树）

适用：按区划、组织、分类、目录、指标体系筛选的列表页。

结构：

```text
业务内容画布
├── 左侧树面板：250-310px
└── 右侧列表面板：自适应
```

规范：

- 当前案例库/问题库默认业务树宽度约 `250px`；区划、组织或长标签树确有需要时可放宽到 `310px`。
- 树宽属于布局变体，必须由内容长度和层级决定，不得每页随意设置。
- 左右区域高度一致、白底；通过 `1px` 轻分隔线组织，不将树做成独立大卡片。
- 树面板只承担筛选和定位，不承载复杂表单。
- 树与列表之间的折叠把手固定在分隔线中部；收起后保留窄轨道和把手。
- 右侧表格工具栏和分页同无树列表。

### 6.4 主列表页（有页签）

适用：按状态切换的列表，如待送审、已送审、全部。

页签样例：

- `待送审 (356)`
- `已送审 (24)`
- `全部 (24)`

规范：

- 页签栏高度约 `48px`。
- 文案使用英文括号，括号前有一个空格。
- 选中态：文字 `#6A8DC4`，底部 `2px` 强调线。
- 未选中态：文字 `rgba(0,0,0,.65)`。
- 页签下方内容区与主面板保留 `16px` 内边距或视觉留白。
- 页签只用于切换同一类数据的状态，不用于切换完全不同业务模块。

### 6.5 主列表页（分页签 > 树）

适用：先按状态切换，再在状态下按树分类筛选。

结构：

```text
页签栏
└── 内容区
    ├── 左侧树
    └── 右侧列表
```

规范：

- 页签优先级高于树。
- 页签栏必须在树与列表的上一层级，横向覆盖整块业务面板；不要只放在右侧列表区域内。
- 树只影响当前页签内的数据范围。
- 左侧树/目录支持收起时，应在树与列表之间的中线位置放置收起把手；展开态显示左箭头，收起态显示右箭头。
- 树收起后只保留窄占位与把手，右侧工具栏、表格和分页自动占满剩余宽度。
- 合理保留结构线：页签栏底线、树/列表中线、表格自身网格线可保留；工具栏、选择提示区、分页区不要再额外增加贯穿整栏的分割线。
- 列表层级优先用留白、选中态、按钮阴影、页签底线和目录把手表达，避免把每个功能区都用线切开。
- 页签切换后保留或重置树筛选要在页面说明中明确。
- 不要同时出现过多页签和过多树层级，避免筛选路径过长。

### 6.6 新增 / 编辑页

适用：全页面新增、编辑、配置维护。

结构：

```text
顶部标题操作栏：64px
└── 表单内容区
    ├── 分组标题
    ├── 两列表单 / 单列表单
    ├── 附件 / 说明 / 关联数据
    └── 底部操作
```

规范：

- 顶部栏白底，高度 `64px`。
- 标题左侧，保存/取消/提交等操作右侧。
- 表单项高度 `32px`。
- 分组标题使用 `16px Semibold`，可加 `4px #6A8DC4` 左侧强调线。
- 桌面端全页面新增/编辑表单默认使用四列标准栅格；备注、说明、附件、长文本等使用整行。
- 全页面新增/编辑是录入态，不得复用详情态结构：不要在表单正文顶部放详情摘要块、状态摘要块、详情页签、使用统计卡片或查看态信息卡。进入表单头后应直接展示分组标题和表单字段。
- 全页面新增的表单头默认只保留当前主操作 `保存`；除非用户明确确认该页面承担提交、入库、发布等流程动作，不要把多个主流程按钮提前放在表单头。
- 表单正文左右边距按 `24px` 控制；分组标题与字段之间保持约 `16px` 垂直节奏；字段标签按 `14px / 22px` 节奏展示，标签到控件约 `8px`；控件高度固定 `32px`，圆角 `4px`。
- 带 AI 处理概览、字段建议或质量问题的处理页，左侧主表单可降为三列 `ufsp-ledger-form-grid`，右侧单独预留一列作为 AI 概览，不把 AI 信息插入表单字段流中。
- 全页面表单头部复用 `ufsp-form-head / ufsp-form-title / ufsp-form-actions`，返回按钮、标题和操作区位置保持一致；同时存在保存和主流程按钮时，保存放在主流程按钮左侧并使用蓝色描边二级按钮。
- 底部操作按钮顺序：次级操作在左，主操作在右。

### 6.7 详情页

适用：查看单据、模板、台账、问题详情。

结构：

```text
标题 / 面包屑
├── 基本信息
├── 业务信息
├── 整改 / 审核 / 流程信息
├── 附件
└── 日志
```

规范：

- 标题常用 `20px Semibold`。
- 面包屑可显示为 `模块名 / 详情`。
- 使用全页面操作栏时，标题采用最短且不歧义的页面身份；系统菜单已表达模块位置时，不强制重复模块名或长面包屑。
- 详情字段使用 label/value 对齐，label 右对齐或弱化，value 保持主文本色。
- 只读信息不要做成禁用输入框，优先使用 Descriptions / 静态文本。
- 可编辑入口放在标题栏右侧，如 `修改`。
- 使用横向顶部操作栏的全页面详情，应让页头、摘要和正文组成连续白色业务页面；不要在浅灰画布上另起多张悬浮卡片。内容分区优先使用留白、节标题、浅底状态和必要弱分隔，文书纸张、附件预览等独立载体可保留自身边界。
- 详情页不直接套用新增编辑页的蓝色竖线分节标题；同名信息已由页头、摘要或左侧定位表达时，下一级区域应删去重复标题，仅保留真正帮助定位的标题。

### 6.8 弹窗页

适用：删除确认、退出确认、废除确认、销号确认、错误提示。

规范：

- 短确认弹窗旧原型约 `345px × 154px`。
- 标题 `20px`，正文 `14px`。
- 内容左侧可配提示图标。
- 操作按钮右对齐：`取消` 在左，`确定` 在右。
- 删除、废除等危险操作应使用错误色或 Popconfirm/Modal.confirm。

### 6.9 抽屉页

适用：快速录入、查看详情、关联数据、复杂筛选、列显示配置。

规范：

- 抽屉阴影：`0 4px 12px rgba(0,0,0,.15)`。
- 标题：`20px Semibold`，主文本色。
- 小标题：`16px Semibold`，可配 `4px #6A8DC4` 左侧边。
- 内容区内边距建议 `24px`。
- 底部固定操作区：`保存/确定` 主按钮，`取消` 三级按钮。
- 简单详情使用单列；录入或对比使用两列。
- 抽屉宽度按内容分级：轻量选择/说明约 `480px`，标准录入/详情约 `640-720px`，双列对比或复杂配置约 `900-960px`；最终宽度仍需结合当前场景确认，不从单个旧页面直接固化。
- 超过标准抽屉承载能力的复杂录入、审核和跨区对比，改用全页面工作区，不继续加宽抽屉。

### 6.10 AI 佐证一致性校验页

适用：提交前 AI 校验、审核前 AI 校验、附件与录入内容一致性比对。

结构：

```text
顶部标题操作栏
├── 左侧：返回 + 页面标题
└── 右侧：刷新状态 / 推理过程 / 提交
内容区
├── 左侧：本次带入数据统计 + 可勾选项目列表
└── 右侧：项目级结论摘要 + 字段异常明细
```

规范：

- 顶部只放页面级动作。AI 校验结果按数据项/项目统一返回，不按字段独立保存；异常明细区只提供当前数据级“修改”入口，顶部不得再重复放“处理异常项”。
- 当前数据修改后进入异步校验状态：左侧项目行置灰、禁用勾选和切换，不参与提交；右侧显示“正在校验”提示。顶部操作使用“刷新状态”刷新校验结果，结果返回后再恢复可选和正常明细展示。
- “修改”应进入原系统风格的完整编辑页，而不是重新设计一个局部修改抽屉；保存后回到校验页并触发当前数据异步校验状态。
- 页面主按钮文案保持“提交”。当用户点击提交且仍有异常时，弹出异议留痕确认；弹窗只保留“取消 / 仍然提交”。用户必须填写情况说明或上传至少 1 张证明截图后，“仍然提交”才允许点击，证明截图支持多张上传。
- 不要同时在标题栏、结论区和明细区重复展示同一个“存在异常”状态；结论区应承担项目级状态表达。
- 结论区先回答“当前项目是否全部一致”，再展示当前项目、异常字段数、异常事实数和异常类型统计。结论区应与页面白色整体底融合，不使用孤立统计卡片堆砌；推荐使用左侧状态线、强标题、辅助说明和紧凑统计组。
- 左侧概览只承担筛选和快速定位作用，使用“全部数据 / 全部一致 / 存在异常”作为可点击筛选项；不展示“本次提交校验”“多条提交”“从列表带入”等低价值说明文案。
- 批量提交时，左侧项目列表只展示从列表页带入的项目，默认全部勾选；最终提交只对勾选项生效。不要为了演示填充无关项目。
- 来源列表存在动态表头时，左侧不应挑选固定业务字段做项目卡片，而应展示整行数据快照：左侧固定勾选框和带入顺序号，中间按原表字段横向滚动，右侧固定显示校验结果。不要再次展示原表序号，避免与带入顺序混淆。字段列保持紧凑，长文本默认省略，悬停后展示完整内容，不为少数字段扩大整体列距。
- 左侧统计、项目行、右侧字段明细默认采用无边框或弱边框设计，通过选中底色、文字层级、行距、浅底分组、圆角行面和状态色表达层级；不得使用卡片套卡片、重边框、内阴影、尖锐直角块或大面积封闭面板堆层级。
- 页面小节标题、辅助说明、数量统计和轻量操作应先评估横向空间；宽屏下优先单行排布，只有窄屏或信息组确实独立时才纵向堆叠。
- 列表和明细区避免使用贯穿整块高度的强调竖线或硬选择线；优先用选中底色、圆角行面、文字权重、小状态文案或轻量标签表达状态。
- 异常明细按字段分组；每个字段下按待核验事实逐条展示：录入原文、佐证附件、附件原文、判断原因和修改/补充建议。
- 整改措施、问题描述等富文本字段必须先拆解为完整关键事实，再逐条匹配证据。不要只展示格式化后的字段摘要，也不要把录入和附件原文压缩成两个大文本框。
- 富文本字段的每条待核验事实需要保留原始描述口径：展示事实标签、录入原文段落、佐证附件名称/页码、附件原文段落、不一致类型、判断原因和修改建议，便于用户判断 AI 拆解和匹配是否可信。
- 字段/事实行只展示录入原文、佐证原文、判断原因和建议，不承载保存类操作，避免同一条数据内出现多个保存入口。
- 推理过程默认收起，通过“推理过程”进入抽屉；主页面只保留结论、统计和需要用户处理的异常依据。

### 6.11 智能检索页

适用：案例库、问题库等以自然语言或关键词定位知识内容的页面。当前已确认局部基准为湖南案例库的“检索首页 → 结果页 → 详情页”。

检索首页：

- 首要任务是输入和发起检索，标题、检索框和示例语句应形成一个明确的视觉中心，不使用超大图标、副标题或说明卡分散注意力。
- 标题只表达功能身份，如“案例智能检索”；图标已能表达语义时，不再重复加一层相同意思的文字。
- 主检索框可使用胶囊形态，但输入面和检索按钮必须形成一个整体：按钮在容器内留有明确呼吸间距，不紧贴边缘，不再外套第二层白色底板。
- 示例语句与说明入口优先横向组织并整体居中，避免“标签一行、说明又单独一行”的纵向堆砌。长说明默认收起，由就近信息图标按需展开。
- “最近检索”和“可检索范围”是辅助信息，其对齐、宽度和视觉权重应低于主检索区；不使用无真实依据的“热门排行”营造氛围。

检索结果页：

- 采用“筛选面板 + 单一命令栏 + 连续结果册”。返回、检索、结果数量和排序放在同一行，不再叠加独立页头、重复的“检索结果”标题或当前查询摘要条。
- 紧凑检索框必须复用首页的形态语言，只收缩高度、宽度和按钮尺寸，不改成另一套方角输入框或独立实心按钮。
- 结果数量与排序是同级辅助工具，应组成紧凑右侧工具组：数量突出数字，选项直接写“相关度优先”等完整含义，不重复显示“排序”标签。
- 结果不弱化成纯文字堆，也不拆成多张悬浮卡片。使用一张连续白色结果册，以行间弱分隔、标题字重、相关度信息列和命中片段浅底建立层级。
- 每条结果先回答“是否是用户要找的”：标题、文号/类型/日期/单位、命中片段、相关度和匹配原因优先；“查看详情”和原文图标放入标题行右侧，不设独立操作列卡片。
- 图标已有熟悉语义时，用 `aria-label` 和 `title` 补充可访问性，界面上不再并排相同含义的文字，避免画蛇添足。
- 连续滚动查看时不显示分页。数据不足一屏时，剩余空间必须属于白色业务阅读面，不在结果末尾暴露大块灰色画布。左右主体底线对齐；数据超出时只让结果册内部滚动。
- 筛选面板可收起，但收起入口应保留在原布局轴线上；展开、收起状态的顶线、底线和圆角层级必须一致。

检索详情页：

- 返回入口统一使用圆形轻量按钮 + 左箭头，靠位置和 `title` 说明语义，不放突兀的长文字返回按钮。
- 详情页先表达案例身份和本次匹配结果，再进入命中定位、原文阅读和相似案例；不在页头、摘要和侧栏重复同一组信息。
- 顶部操作栏、案例摘要和三栏阅读区应在同一连续白色工作区内自然接续，不使用“页头横条 + 摘要卡 + 多列卡片”的混合结构；栏间根据阅读列关系选择留白、短分隔或弱结构线，不默认贯穿整页，也不默认完全无分隔。
- 页头只承担页面身份和页面级操作；案例标题、文号和类型等身份信息集中在摘要区表达一次。左侧定位菜单已经显示当前内容类型时，正文区不再重复设置同名标题栏。分隔线不能一概删除或一概保留，应先判断区块关系再分级表达：业务阶段切换可使用全宽弱横线；同一工作区的阅读列可使用上下留白、末端渐隐的短竖线；局部辅助分组可使用缩进短横线。不同层级在线长、方向和透明度上必须有区别，避免全页面无结构，也避免重新画成表格线框。
- 原文阅读区是文书载体，可保留轻阴影和必要边界；匹配原因、相似案例等普通分组以文字层级和浅底为主，相邻关系不清时可增加缩进短线或其他局部分隔。

设计原因：

- 智能检索是“输入—判断—深入阅读”的任务链，每页只应突出当前一步；重复标题、多层容器和多余说明会与主任务争夺注意力。
- 政务业务页的高级感来自尺寸、对齐、层级和稳定性，不来自更多卡片、更大圆角或更重阴影。
- 连续结果册比独立卡片更适合扫描和比较；它能保持稳定阅读轴线，同时通过命中片段和匹配原因提供足够判断依据。
- 空白不是装饰，必须有归属。它要么是提高聚焦的呼吸空间，要么是业务面板内的可扩展阅读面；不得因数据不足而形成与整体结构无关的大块灰底。

## 7. 组件规范

### 7.1 按钮 Button

尺寸：

- 默认高度 `32px`。
- 图标按钮 `32px × 32px`。
- 图标尺寸不大于 `14px × 14px`，至少一边为 `14px`。
- 文字按钮宽度自适应，左右内边距建议 `16px`。

类型：

| 类型 | 背景 | 文字 | 阴影 | 用途 |
| --- | --- | --- | --- | --- |
| 主按钮 | `#1890FF` | `#FFFFFF` | `0 0 2px rgba(24,144,255,.35)` | 查询、保存、确定、新增 |
| 二级按钮 | `#FFFFFF` | `#1890FF` | `0 0 2px rgba(24,144,255,.35)` | 导入、导出、启用、批量设置、查询方案 |
| 三级按钮 | `#FFFFFF` | `rgba(0,0,0,.65)` | `0 0 2px rgba(0,0,0,.35)` | 重置、取消、返回、普通辅助操作 |
| 危险按钮 | `#F5222D` | `#FFFFFF` | `0 0 2px rgba(245,34,45,.35)` | 删除、废除 |
| 禁用按钮 | `#F3F3F3` | `rgba(0,0,0,.25)` | 弱阴影或无阴影 | 不可操作 |
| 文字操作 | 透明 | `#1890FF` | 无 | 表格行操作 |

表格操作顺序：

```text
详情 / 编辑 / 删除 / 更多
```

规则：

- 最多四个占位，只能少不能多。
- 超过四个操作放入 `更多`。
- 可操作文字用 `#1890FF`。
- 不可操作文字用 `rgba(173,173,173,.65)`。
- 删除类操作必须二次确认。
- 工具栏内主流程按钮使用主按钮；导入、导出、查询方案等使用二级按钮；重置、取消等使用三级按钮；删除类使用危险按钮或危险图标按钮。
- 顶部查询区的搜索按钮为主色图标按钮，刷新、筛选、列设置为二级图标按钮。
- 导入/导出按钮必须使用对应语义图标，图标宽高 `14px × 14px`，图标与文字间距约 `6px`，文字居中。
- 业务列表页的新增按钮文案固定为 `新增`，不因录入方式写成 `手工新增`、`人工新增` 等；具体新增方式放到弹窗、抽屉或表单内部选择。
- 工作台账、问题库、案例库等已确认页面的顶部工具栏图标必须复用同一套 iconfont/SVG 原件：新增用 `action-add`，导入用 `action-import`，导出用 `action-export`，提交/入库类批量动作使用提交语义图标；不得在同一类页面混用 Lucide、Ant Design 或自绘图标替代。
- 生命周期类批量动作按业务结果命名，例如案例库使用 `批量入库`，不写成冗长的 `批量确认入库`；没有明确删除语义时，不得在工具栏放独立危险 X 图标。

### 7.2 输入框 Input / Select / DatePicker

通用规则：

- 高度 `32px`。
- 圆角 `4px`。
- 默认无明显边框，使用 `0 0 2px rgba(0,0,0,.35)` 阴影表达边界。
- 占位文字 `rgba(0,0,0,.25)`。
- 聚焦时取消浏览器原生 outline，使用 `0 0 5px rgba(24,144,255,.28-.35)` 弱蓝阴影。

状态：

| 状态 | 规则 |
| --- | --- |
| 默认 | 白底、轻阴影、占位文字 |
| 聚焦 | 蓝色聚焦阴影 |
| 校验通过 | 可使用成功提示，不要过度装饰 |
| 校验失败 | 错误文案在控件下方，错误色 |
| 风险提示 | 使用警示文案，不做强拦截 |
| 不可输入 | 背景 `#F3F3F3`，文字弱化 |

下拉：

- 展开框圆角 `4px`。
- 下拉浮层阴影约 `0 0 4px rgba(0,0,0,.35)`。
- 选项文字 `14px`，选中项可用业务蓝背景或蓝色标记。
- 多选项标签背景可用浅灰，关闭图标 `8px`。

### 7.3 查询区

基础查询：

```text
模糊查询： [请输入] [高级查询] [查询/新增/导出等操作]
```

规范：

- 标签 `14px`，主文本色。
- 输入框宽度常用 `240px`。
- 查询、重置、保存查询方案使用 `32px` 按钮。
- 高级查询为蓝色文字或图标按钮。
- 查询条件回显时使用可关闭标签，支持清空。

列表页右侧固定查询组件：

```text
[请输入] [查询] [刷新] [筛选] [查询方案] [列设置]
```

规范：

- 工作台账录入、工作台账审核、案例库一般案例管理等业务列表页的右侧查询组件必须使用同一固定组合，不得各页面自行改尺寸、间距、颜色、图标尺寸或按钮层级。
- 输入框使用 `ufsp-search-box ufsp-filter-input`，宽度 `240px`，高度 `32px`，圆角 `4px`，白底，轻阴影 `0 0 2px rgba(0,0,0,.35)`，占位文案为 `请输入`。
- 查询使用 `ufsp-icon-btn ufsp-icon-btn-primary`，`32px × 32px`，主蓝底 `#1890FF`，白色 `14px` 搜索图标。
- 刷新、筛选、列设置使用 `ufsp-icon-btn ufsp-icon-btn-secondary`，`32px × 32px`，白底蓝色图标，轻蓝阴影 `0 0 2px rgba(24,144,255,.35)`，图标统一 `14px × 14px`。
- 查询方案使用 `ufsp-btn ufsp-btn-secondary`，高度 `32px`，左右内边距 `16px`，白底蓝字，轻蓝阴影。
- 固定组件顺序为：输入框、查询、刷新、筛选、查询方案、列设置；列设置使用齿轮语义图标，不使用标签、筛选或其他替代图标。

高级查询：

- 点击高级查询图标/文字后展开查询方案面板。
- 支持字段选择、条件关系、值输入、日期区间。
- 多值查询文案规则：若某条件支持多个值，可选择“包含”，值用中英文逗号分隔。
- 查询后普通查询和规则查询都应回显查询条件，条件可关闭。
- 保存查询方案时弹出名称输入。

### 7.4 表格 Table

表格是业务页面主组件，规范应优先保持一致。

表头：

- 背景：`#6A8DC4`
- 文字：`14px Semibold #FFFFFF`
- 行高：`32px`
- 对齐：居中
- 左右表头圆角 `4px`

表体：

- 文字：`14px rgba(0,0,0,.65)`
- 行高：`32px`
- 边框：`1px #E4E4E4`
- 行悬停：`#F6F6F6`
- 最后一行两端保持 `4px` 圆角

对齐：

| 数据类型 | 对齐 |
| --- | --- |
| 数字、金额 | 右对齐 |
| 普通文字 | 左对齐 |
| 时间、状态、编码、固定长度字段 | 居中 |
| 操作列 | 居中或右对齐，按页面密度确定 |

可点击字段：

- 唯一字段或单据编号可点击查看详情。
- 悬停色和下划线使用 `#1890FF`。

复选框：

- 尺寸 `14px × 14px`。
- 未选中：圆角 `2px`，轻阴影。
- 已选中：背景 `#6A8DC4`，圆角 `2px`。
- 支持全选、部分选中。

冻结列：

- 横向可滚动的业务表格，勾选列默认左侧冻结。
- 用于识别记录的主字段列（如问题标题、案例标题、项目名称、专项检查领域等）应跟随勾选列左侧冻结，避免滚动后失去行身份。
- 操作列默认右侧冻结，背景必须跟随普通、悬停、选中三种行状态同步，不能出现固定列色块断层。
- 表格横向滚动容器不得用左右 `padding` 制造页面留白；`position: sticky; right: 0` 会以滚动容器内边缘为吸附边界，容器内 `padding` 会导致操作列拖拽后穿透到表格外侧留白。页面边距应放在滚动容器外层，用 `margin` 或外层包裹控制。
- 冻结列所在滚动容器应负责裁切和承载表格边界：建议 `overflow: auto`、`border-radius: 4px`、白底；冻结单元格保持不透明背景，可加 `background-clip: padding-box`；右侧操作列加轻量左分隔线或 `box-shadow: -1px 0 0 #E4E4E4`，避免覆盖正文时边界不清。

分页：

- 文案：`共 X 条`、`跳至 X 页`、`X 条/页`。
- 字号 `14px`，文本色 `rgba(0,0,0,.65)`。
- 输入/选择控件圆角 `4px`，轻阴影。
- 主列表页默认使用简版居中分页：`共 X 条` + `上一页` + 当前页码 + `下一页` + `X 条/页`。
- 当前页码使用 `#6A8DC4` 填充、白色文字；上一页/下一页和条数选择器使用白底轻阴影。
- 只有数据量较大或业务要求精确跳转时，才补充 `跳至 X 页` 输入框。

### 7.5 数据标识 Tag / Status

常见状态：

- 待送审
- 流程中
- 被退回
- 已办结
- 启用中
- 已停用

列表标识：

- 使用圆点 `●` + 状态文字。
- 状态标识应靠近主字段或状态列，不要散落在多列。

退、超、临标识：

| 标识 | 含义 | 规则 |
| --- | --- | --- |
| 退 | 被退回 | 最高优先级 |
| 超 | 超期 | 次优先级 |
| 临 | 临期 | 次优先级 |

优先级：

```text
置顶权重：退 > 超 > 临
覆盖权重：退 > 超 = 临
```

交互：

- 鼠标悬停标识时展示说明浮层。
- 退回说明示例：`退回说明：佐证材料与实际情况不匹配，请复核后再上传`。
- 多条提示间距 `10px`。
- 取消一条提示后，下一条向上补位。

### 7.6 树 Tree

适用：区划树、组织树、分类树、指标树。

规范：

- 复选框 `16px × 16px`。
- 数据选中色：`#E6F7FF`。
- 鼠标悬停色：`#F6F6F6`。
- 树节点文本 `14px`。
- 支持：未勾选、全选、部分勾选、勾选、禁止取消、禁止勾选。
- 可有图标，也可无图标，但同一页面内保持一致。
- 操作可包含：全部展开/收起。

### 7.7 表格编辑

适用：可编辑单元格、表格内快速录入。

规范：

- 可编辑单元格默认看起来像普通单元格。
- 点击或聚焦后显示输入态。
- 聚焦底色：`#E6F7FF`。
- 不要在表格内堆叠复杂校验，错误说明可在单元格下方或保存时统一提示。

### 7.8 附件 Upload

附件列表字段：

- 文件名称
- 文件大小
- 上传时间
- 操作

操作：

- 预览
- 删除
- 下载

上传区：

- 文案：`点击或将文件拖拽到这里上传`
- 扩展名说明：`支持扩展名：.rar .zip .doc .docx .pdf .jpg...`
- 必填材料用 `*` 标识。
- 材料要求放在上传区下方或右侧说明区。

附件预览：

- 可使用弹窗或抽屉。
- 文件名过长时单行省略，悬停显示完整名称。

### 7.9 目录 Anchor

适用：详情页、长表单页。

目录项：

- 字号 `14px`
- 颜色 `#797979`
- 当前项可用主蓝或左侧标记强调。

目录标题：

- `18px Semibold`
- 颜色 `rgba(0,0,0,.85)`

常见目录：

- 基础信息
- 整改措施及情况
- 问题类型及金额
- 佐证材料

### 7.10 日志 Timeline

流程日志字段：

- 时间
- 操作类型
- 操作人
- 节点
- 状态
- 审核意见

常见状态：

- 新增
- 提交
- 审核
- 通过
- 退回
- 撤回
- 进行中

交互：

- 审核意见过长时默认收起，悬停或点击查看。
- 日志按时间倒序或流程正序需在页面 spec 中说明。

### 7.11 弹窗 Modal / Confirm

常见场景：

- 暂未保存，确定退出么？
- 确定要删除这 8 项吗？
- 确定要废除这 2 项吗？
- 确定要销号这 2 项吗？
- 操作错误提示

规范：

- 简单确认用 Modal/Popconfirm。
- 强提示标题使用 `20px`。
- 正文使用 `14px`。
- `取消` 在左，`确定` 在右。
- 危险确认的确定按钮使用危险色。

### 7.12 列显示设置

适用：列表字段配置、冻结列、列宽设置。

结构：

```text
列显示设置抽屉
├── 搜索字段
├── 全部字段
├── 已选字段
├── 字段配置
│   ├── 显示
│   ├── 字段名
│   ├── 冻结
│   └── 列宽（px）
└── 保存 / 取消
```

规范：

- 支持全选/取消。
- 已选字段和全部字段视觉上区分。
- 列宽单位明确为 `px`。
- 冻结列使用开关或复选框，不使用自由文本。

### 7.13 全屏

适用：大表格、大配置页、复杂看板。

规范：

- 全屏态隐藏顶栏、菜单和外部业务导航，只保留当前业务模块。
- 提供明确 `退出全屏`。
- 全屏不是浏览器真正全屏的唯一形式，可以是业务区域最大化。
- 表格列、查询区和分页在全屏态保持同样样式，不重新设计。

## 8. 交互规范

### 8.1 查询

- 默认展示基础查询。
- 高级查询默认收起。
- 点击查询后结果列表刷新，并回显条件。
- 重置恢复默认条件。
- 已保存查询方案不影响本次临时查询条件，除非用户明确选择应用方案。

### 8.2 新增 / 编辑 / 查看

- 新增复杂对象可进入全页面新增布局。
- 轻量新增可用抽屉。
- 查看详情优先详情页或抽屉详情，不使用弹窗承载大段信息。
- 编辑入口应靠近详情标题或表格操作列。

### 8.3 删除 / 退回 / 废除 / 销号

- 必须二次确认。
- 退回必须填写退回说明。
- 删除、废除、销号的确认文案要包含数量或对象名称。
- 原型层面不实现复杂业务校验，只展示必要提示。

### 8.4 表格操作

- 单行操作最多四个：详情、编辑、删除、更多。
- 批量操作放在表格上方工具栏。
- 批量操作前需要勾选行；未勾选时按钮可禁用。
- 鼠标悬停行用 `#F6F6F6`。

### 8.5 反馈

- 成功：轻量 Message。
- 删除/废除/销号：Confirm。
- 表单未保存离开：Confirm。
- 操作错误：Modal 或 Alert。
- 加载：表格 Spin/Skeleton。
- 空状态：使用轻量 Empty，不要大面积插画。

## 9. Codex 生成业务页面约束

后续让 Codex 新增业务页面时，可直接引用本节。

### 9.1 必须做

- 完整页面必须复用公共 `TopBar`，并按“系统功能菜单 → 业务核心区”组织。
- 有业务树/目录的列表页必须按“系统功能菜单 → 业务树/目录 → 列表工作区”组织。
- 页面外部使用浅灰蓝画布，系统功能菜单和业务核心区使用白色面板。
- `#E6F7FF` 只用于树选中、分隔把手和局部轻反馈，不强制铺满业务核心区。
- 控件高度默认 `32px`。
- 表格按本规范设置表头、行高、对齐、操作列和分页。
- 使用本地 mock 数据。
- 对风险、状态、退/超/临等字段保留解释字段，例如 `riskReason`、`dataStatus`、`scoreSource`。
- 页面级说明或实现文档要说明采用本规范。

### 9.2 禁止做

- 不要重新实现 TopBar、用户信息、通知和全局搜索。
- 不要在业务核心区内重复生成系统功能菜单。
- 不要省略系统功能菜单后直接把业务树放在页面第一列。
- 不要接真实接口。
- 不要实现数据库、权限、真实业务计算公式。
- 不要引入新的 UI 库。
- 不要把工作台、全景分析、首页的卡片风格混入业务操作页。
- 不要把 Axure 绝对坐标直接搬进 React；要转成 flex/grid/Ant Design 组件布局。

## 10. 页面生成检查清单

新增业务页面完成前，至少检查：

- [ ] 是否按 1920 × 1080 主要视口校准整体密度，并保持自适应高度。
- [ ] 是否复用公共 TopBar 和已确认系统功能菜单。
- [ ] 有业务树时，是否保持“系统功能菜单 → 业务树 → 列表”顺序。
- [ ] 是否使用浅灰蓝外部画布 + 白色菜单/业务面板结构。
- [ ] 查询区、按钮、表格、分页是否保持 32px/4px/14px 的基础规范。
- [ ] 业务面板和卡片是否统一为 8px 圆角，仅胶囊检索框、圆形返回按钮等语义形态例外。
- [ ] 同屏标题、图标、当前查询、操作文字是否存在重复表达，可删减的是否已删减。
- [ ] 数据不足一屏时，留白是否属于业务面板或明确的呼吸区，而不是暴露大块无意义画布。
- [ ] 宽屏下的辅助信息和轻操作是否尽量横向组织，避免不必要的纵向堆砌。
- [ ] 表格字段对齐是否正确：金额右、文字左、时间/状态/编码居中。
- [ ] 行操作是否控制在 4 个以内，更多操作是否收纳。
- [ ] 状态、退/超/临、风险说明是否有清晰展示。
- [ ] 抽屉、弹窗、确认框是否使用正确场景。
- [ ] 是否全部使用 mock 数据，没有真实接口和权限逻辑。

## 11. 页面范式分类结论

| 页面类型 | 当前默认骨架 | 主要参考 | 不应混入 |
| --- | --- | --- | --- |
| 业务列表（无树） | 系统功能菜单 + 页签/工具栏 + 表格 + 分页 | 问题库、旧“主列表页布局（无树）” | 首页指标卡、重复页面标题块 |
| 业务列表（有树） | 系统功能菜单 + 业务树 + 列表 | 案例库、问题库、旧“主列表页布局（有树）” | 把业务树当系统菜单 |
| 状态页签 + 树 + 列表 | 系统功能菜单 + 跨栏页签 + 树/列表 | 案例库一般案例管理、问题库台账 | 页签只放在列表右侧 |
| 新增/编辑 | 系统功能菜单 + 64px 表单页头 + 分组表单 | 案例库新增编辑、问题库编辑页、旧全页面新增 | 详情摘要卡、重复页签、多个无依据主按钮 |
| 详情/审核/处理 | 系统功能菜单 + 64px 页头 + 信息分组/处理区 | 问题库审核校验、案例库处理页、旧详情模板 | 每个字段独立保存、卡片套卡片 |
| 抽屉/弹窗 | 当前页上层覆盖，按轻量/标准/复杂分级 | 高级查询、列显示、附件、确认弹窗 | 用弹窗承载长表单或完整流程 |
| 首页 | TopBar + 多模块总览网格 | `fiscal-supervision-home2` | 业务树、标准业务表格骨架 |
| 工作台 | TopBar + 流程/任务/分析模块 | `supervisor-workbench` 等 | 生搬列表页三段式结构 |
| 智能检索 | 聚焦检索首页 + 筛选/命令栏/连续结果册 + 定位阅读详情 | 湖南案例库案例检索 | 重复页头、卡片套卡片、孤立操作列、无归属大块留白 |

首页、工作台和业务页共享颜色、字体、间距、弱边界和状态语义，但不共享同一页面骨架。设计语言可以统一，页面范式必须按任务目标选择。
