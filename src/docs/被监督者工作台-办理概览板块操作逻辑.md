# 被监督者工作台 - 办理概览板块操作逻辑

## 一、板块整体结构

办理概览板块位于被监督者工作台页面中间左侧，由 **3 个子模块** 组成：

| 区域位置 | 模块名称 | 功能定位 |
|----------|----------|----------|
| 上左 | **当前需响应** | 按"用户要做的动作"拆分展示待办事项 |
| 上右 | **优先处理依据** | 动态展示最紧急/最重要的事项类型（最多3项） |
| 下方 | **经办事项进展** | 跟踪已提交/已处理事项的流转状态 |

板块顶部还有 **当前重点提醒** 条，用一句话概括最优先处理的事项，点击可打开处理依据说明抽屉。

## 二、核心数据流向

### 2.1 数据来源

所有数据来源于本地 mock 数据 `todos`，经过多层加工后驱动界面。

### 2.2 基础数据加工

每条事项会被附加 7 个计算字段，形成 `TodoOverviewItem`：

| 字段 | 类型 | 说明 |
|------|------|------|
| `timing` | `TodoTiming` | 时限状态：`overdue`（超期）/ `due`（临期）/ `normal`（正常） |
| `dueDays` | `number` | 距离截止天数（负数表示已超期） |
| `statusGroup` | `TodoStatusGroup` | 状态分组：待处理/审核中/被退回/已完成/已销号 |
| `disposalPool` | `TodoDisposalPool` | 处置池：`action`（待办）/ `returned`（退回）/ `tracking`（跟踪）/ `history`（历史） |
| `flowStage` | `TodoFlowStage` | 流程节点：待我处理/退回待补正/已提交待审核/审核复核中/待销号/已完成 |
| `category` | `string` | 事项分类：线索核验/资金复核/整改进度/材料补正/报告报送 |
| `responseAction` | `string` | 应办动作：退回待补正/待首次处理/待补充说明/待更新进度/待提交 |

## 三、交互操作逻辑

### 3.1 筛选联动（核心交互）

#### 状态变量

`overviewFilter` 是办理概览板块的核心状态，类型为 `TodoOverviewFilter | null`：

```typescript
type TodoOverviewFilter = { 
  kind: 'response' | 'tracking' | 'deadline' | 'category' | 'risk' | 'progress'; 
  value: string; 
  label: string;
};
```

#### 操作流程

```
点击概览区域任意卡片
       ↓
调用 applyOverviewFilter(filter) 函数
```

## 四、当前需响应模块

### 4.1 模块定位

当前需响应展示当前需要本单位直接操作的事项数量，按"用户要做的动作"拆分，是办理概览中的主视觉区域，宽度权重高于优先处理依据（占 7/12 宽度）。

代码位置：[index.tsx#L2061-L2101](file:///Users/edwardm/Documents/trae_projects/UFSP2.0/src/prototypes/supervised-workbench/index.tsx#L2061-L2101)

### 4.2 应办动作类型

共 5 种应办动作，按优先级排序：

| 序号 | 动作类型 | 判断规则 |
|------|----------|----------|
| 1 | 退回待补正 | 状态包含"被退回"或"退回" |
| 2 | 已上传未提交 | 特殊判断（见 3.1.4） |
| 3 | 待补充说明/材料 | 文本包含"补录/附件/材料/补充/佐证" |
| 4 | 待更新整改进度 | 文本包含"进展/进度/压降/督办/整改" |
| 5 | 待提交/重新提交 | 文本包含"报告/周报/报送/上报/导出" |
| 6 | 待首次处理 | 以上都不满足时的默认值 |

### 4.3 展示规则

- 隐藏数量为 0 的动作卡片
- 按上述优先级排序

- 已上传未提交单独展示，避免用户误以为材料上传后流程已经送审

## 五、优先处理依据模块

### 5.1 模块定位

优先处理依据是动态模块，不固定写死为"时限优先级"。不同主题按可用字段选择展示方式。

代码位置：[index.tsx#L2103-L2141](file:///Users/edwardm/Documents/trae_projects/UFSP2.0/src/prototypes/supervised-workbench/index.tsx#L2103-L2141)

### 5.2 动态模式判断

优先处理依据会根据数据情况 **自动选择展示模式**，判断顺序：

```
有退回待补正 或 已上传未提交？
       ↓ 是
  「按阻塞与时限混合」模式
       ↓ 否
  有超期 / 今日到期 / 1-3日到期？
       ↓ 是
  「按时限优先」模式
       ↓ 否
  有高风险事项？
       ↓ 是
  「按风险优先」模式
       ↓ 否
  「按事项状态优先」模式
```

## 六、经办事项进展模块

### 6.1 模块定位

经办事项进展展示本单位已经处理过、提交过、补正过、更新过或上传过材料但尚未完全结束的事项，让用户知道事项当前流转到哪个环节。

代码位置：[index.tsx#L2143-L2184](file:///Users/edwardm/Documents/trae_projects/UFSP2.0/src/prototypes/supervised-workbench/index.tsx#L2143-L2184)

### 6.2 统计范围

包括：
- 我提交过的事项
- 我补正过的事项
- 我更新过进度的事项
- 我上传过材料但尚未办结的事项
- 我主动关注的事项

不包括：
- 完全未处理的待办事项
- 已归档很久的历史事项
- 与当前用户无经办关系的事项

### 6.3 展示内容

| 内容 | 说明 |
|------|------|
| 流程节点分布 | 待审核、审核/复核中、待销号（数量>0 时显示） |
| 特殊状态 | 已退回需处理、已上传未提交 |
| 关注事项 | 我关注的事项数量 |
| 等待时长 | 最长等待天数 |
| 反馈时间 | 最近反馈日期 |
| 未反馈提示 | 超过 5 天未反馈的事项数量提示 |

## 九、设计理念

办理概览板块的核心设计理念是 **"左侧判断、右侧办理"**：

- **左侧（办理概览）**：用概览帮用户快速判断"先办什么、为什么"，提供行动导向的事实概览
- **右侧（待办列表）**：承接左侧筛选结果，展示具体事项，点击进入办理

左侧不重复右侧的数量汇总，不做原因分析、整改建议、规则解释或案例推荐，这些内容放到底部智能辅助分析区或事项详情页。
