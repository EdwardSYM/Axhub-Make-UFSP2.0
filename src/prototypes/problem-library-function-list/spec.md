# 问题库工作台账录入与审核功能列表页

## 1. 业务与功能

### 1.1 核心目标

本页面将“重点领域整改功能列表页”复制为问题库下的独立原型入口，用于演示问题库中“专项问题整改 / 台账分发录入 / 工作台账录入”和“工作台账审核”的列表页，以及录入、审核阶段口径一致的 AI 智能校验流程。

页面只做前端静态演示：使用本地 mock 数据，不接入后台接口、权限、数据库、真实业务公式或真实 AI 校验能力。

### 1.2 功能清单

- **问题库功能菜单**：保留工作台返回、台账分发录入、问题整改更新、整改明细查询等功能节点，支持展开/收起，并独立维护在本目录。
- **工作台账录入列表页**：按列表页规范展示页签、左侧年度/主题树、工具栏、查询区、紧凑表格、居中分页和行操作。
- **AI智能校验**：点击“提交校验”后进入 AI 校验工作区，页面只承接列表页已勾选的数据，展示“全部一致 / 存在异常”两类用户结论，并将问题类型收敛为“一致性 / 合规性”两类。
- **工作台账审核列表页**：点击左侧“工作台账审核”进入待审核列表，列表顶部“审核”用于选择单条或多条数据进入审核校验，最终结果动作在审核校验页内拆成“通过 / 退回”。
- **审核校验工作区**：审核页结构与录入校验页同源，继续按当前台账、佐证材料和制度依据统一校验，不再拆成“录入阶段只校验一致性、审核阶段另行校验合规性”两段逻辑，并给出“建议通过 / 建议退回”。
- **审核数据状态**：审核页只使用“全部一致 / 存在异常”。“全部一致”表示当前数据未发现一致性或合规性异常；“存在异常”包括一致性问题、合规性问题、资料支撑不足或无法判断等需要人工复核的数据。
- **由列表选择决定校验范围**：列表勾选 1 条则左侧只出现 1 条，勾选多条则左侧只出现这些已勾选条目，不再展示全量 17 条项目。
- **批量/单条同类校验页**：批量提交与单条提交复用同一套校验页结构；差异只体现在左侧承接项目数量和统计口径，右侧始终按当前选中项目展示结论与异常明细。
- **异常项页内处理**：异常明细提供当前数据级“修改”入口、富文本事实拆解、保存后异步校验和提交风险确认，用于演示用户不必返回列表即可处理问题。

### 1.3 交互要点

- 点击左侧功能节点：在本独立页面内切换 `feature` 参数；除“工作台账录入”和“工作台账审核”外展示功能占位。
- 点击“工作台账审核”：展示待审核、已审核、全部页签，以及待审核列表、搜索、审核、废除、销号、导出等操作。
- 点击页签：切换待提交、已提交、全部的静态列表视图。
- 勾选表格行：改变页面选择态；选择 1 条进入单条校验，选择多条进入批量校验。
- 点击“提交校验”：切换到 AI 校验工作区，短暂展示“AI正在校验录入信息与佐证材料，请稍候……”。
- 点击审核列表顶部或行内“审核”：进入审核校验工作区，直接查看随流程带入的智能校验结果，不在审核岗提供重新校验动作。
- AI 校验工作区顶部采用新增/编辑页规范：左侧圆形返回图标 + “工作台账录入 / 提交校验”标题，右侧只放页面级动作“刷新状态 / 推理过程 / 提交”。
- 审核校验工作区顶部采用同样结构：左侧圆形返回图标 + “工作台账审核 / 审核校验”标题，右侧只放页面级动作“推理过程 / 通过 / 退回”。
- 单条校验：左侧仅出现当前单条数据，并默认勾选；右侧展示该条项目的唯一校验结论和异常明细。
- 多条校验：左侧仅出现列表页传入的多条项目，并默认全选；用户取消勾选后，提交只对仍被勾选的项目生效。
- 数据选择：左侧概览只保留“全部数据 / 全部一致 / 存在异常”筛选入口；下方展示从列表带入的整行数据快照，左侧固定勾选框和带入顺序号，右侧固定校验结果，中间字段可横向滚动；选中具体数据后，右侧展示该数据异常明细。
- 校验结果表达：页面级状态只保留“全部一致 / 存在异常”；证据不足、无法判断等内部类型只在异常明细中作为字段结论或问题原因出现。
- 审核结果表达：审核页与录入页使用一致的结论和统计结构，左侧展示“全部一致 / 存在异常”结论，右侧统计“异常事实 / 合规性问题 / 一致性问题”；不再展示“前置异常 0”或“历史 AI 一致性”等旧口径摘要。
- 点击“刷新状态”：刷新当前校验结果状态；若存在保存后正在异步校验的数据，刷新后恢复可选并展示最新静态校验结果。
- 点击“推理过程”：打开右侧抽屉查看材料匹配、字段提取和比对过程，默认页面只展示一行摘要。
- 点击审核页“推理过程”：打开右侧抽屉查看当前台账、佐证材料、制度依据的统一校验过程，以及一致性 / 合规性问题归类。
- 点击异常明细标题区的“修改”：进入原系统风格的“工作台账录入 / 编辑”全页表单，按原录入页结构修改当前数据，不在每个字段事实行上放保存入口。
- 点击编辑页“保存”：返回提交校验页，当前数据进入异步校验状态；左侧该项目置灰且不可勾选/切换，不参与提交，右侧显示“正在校验”；点击顶部“刷新状态”后恢复正常结果展示。
- 点击异常事实级“标记不认可”：仅作为录入岗个人对单条 AI 判断的参考标记，不改变系统“存在异常”的结论，也不作为审核结论。
- 点击当前数据级“不认可说明”：在录入校验页“异常项明细”标题区显示入口；右侧抽屉支持文本说明和多张图片上传，用于向审核岗解释为什么不采纳 AI 建议或为什么仍然提交，所有内容均选填。
- 点击“提交”：若当前勾选范围仍有异常，只弹出风险确认；弹窗提示建议修改或补充“不认可说明”，不再承载说明填写或图片上传，用户可“仍然提交”。
- 点击当前数据级“不认可说明”：在审核页“审核异常明细”标题区显示入口；右侧抽屉只读展示录入岗对 AI 异常的标记、说明和证明截图。
- 点击当前数据级“审核说明”：在审核页“审核异常明细”标题区显示入口；右侧抽屉先只读展示历史审核岗说明和截图，再记录当前审核岗选填审核说明和多张图片；后续多级审核按岗位累计追加。
- 点击审核页“通过”：若勾选范围全部一致则直接通过；若勾选范围存在异常，只弹出风险确认，提示建议查看异常明细或补充审核说明，用户可确认通过。
- 点击审核页“退回”：不再弹出逐条退回说明弹窗，直接按当前勾选范围退回；若某条数据已填写审核说明则作为退回留痕，否则仅随系统异常摘要留痕。

### 2.2 数据来源

- **数据类型**：功能菜单、台账录入列表、台账审核列表、AI 校验结果、审核校验结果、异常项明细。
- **数据源**：页面内本地 mock 数据。
- **关键字段**：
  - `projectName`：项目名称。
  - `unit`：所涉单位或所属单位。
  - `description`：问题具体描述。
  - `dataStatus`：静态数据状态说明。
  - `fieldName`：AI 异常项字段名称。
  - `inputValue`：用户录入内容。
  - `attachmentValue`：附件提取内容。
  - `facts`：整改措施、问题描述等富文本字段拆解后的待核验事实，每条事实包含录入原文、附件来源、附件原文、判断原因和建议。
  - `inputRichText` / `attachmentRichText`：整改措施、问题描述等富文本字段的原始分段内容。
  - `source`：附件来源。
  - `suggestion`：面向用户的修改或补充建议。
  - `previousAiStatus`：列表历史留痕中的录入岗提交状态，仅用于说明录入岗是否曾在异常情况下继续提交，不作为审核页主校验口径。
  - `reviewRequirement`：本条数据对照审核标准的静态结果，取值为“通过 / 不通过”。
  - `reviewStandard`：审核标准或制度要求文本。
  - `auditSuggestion`：审核建议，取值为“建议通过 / 建议退回”。
  - `previousSubmitProofs`：录入岗在“存在异常仍提交”时补充的不认可说明和证明截图。
  - `aiRejectMarks`：录入岗对单条待核验事实的“标记不认可”，仅供审核参考和模型优化，不改变异常结论。
  - `aiRejectNote`：录入岗对当前数据级不认可判断的解释说明和证明截图。
  - `submitterRejectMark`：录入岗是否对单条 AI 判断标记不认可，取值为“录入岗已标记不认可 / 录入岗未标记不认可”，仅供审核参考。
  - `auditReviewNote`：审核岗对当前数据级异常的审核说明和证明截图，按岗位累计，均不强制填写。

### 2.3 内容示例

- 列表页示例主题：地方政府债务。
- AI 校验默认由列表页勾选数据决定承接条数；单条提交只展示 1 条，多条提交只展示被勾选的多条。
- 多条示例中，左侧统计展示本次带入条数、全部一致数量、存在异常数量和需复核异常项数量，默认全选。
- 存在异常示例包含整改措施富文本拆解：按一致性、合规性两类问题类型分别与附件原文和审核规范比对，用于演示从录入阶段就纳入审核标准的判断口径。
- 审核列表示例默认勾选 3 条数据，覆盖多种情况：既有合规性问题，也有一致性问题；既有录入岗已标记不认可，也有录入岗未标记不认可，避免只展示单一数据状态。
- 审核校验异常明细按“一致性 / 合规性”问题类型组织，并展示“录入原文 / 佐证附件或审核依据 / 判断原因”；事实行同步展示录入岗是否标记不认可，录入岗不认可说明独立进入“不认可说明”抽屉，审核建议只在结论摘要层表达，不在每条事实里重复展示。

## 3. 布局与结构

### 3.1 整体布局

- **布局模式**：顶部导航 + 左侧功能菜单 + 右侧业务内容区。
- **容器宽度**：外层沿用当前项目 `max-width: 1920px` 的工作台框架。
- **关键尺寸**：
  - 左侧功能菜单：展开 `260px`，收起 `64px`，收起/展开控制放在标题区右侧或折叠态顶部。
  - 业务内容区：列表页可保留轻蓝画布；提交校验工作区最外层采用白色整体底，靠弱分隔线和轻量背景块组织层级，避免白卡片漂浮在灰蓝底上。
  - 列表状态页签：`48px`，位于业务树和表格的上一层级，横向覆盖业务面板。
  - 左侧业务树：展开 `250px`，收起后保留 `18px` 占位与中线把手。
  - 工具栏：约 `56px`。
  - 表格行高：`32px`。
  - 分页：底部居中，`共 X 条 / 上一页 / 当前页 / 下一页 / 20 条/页`。
  - 新增/校验页顶部栏：`64px`。
  - AI 校验区：左侧本次提交统计与整行数据快照表约 `460px`，右侧结论、异常明细、页内处理入口自适应。
  - 审核校验区：沿用 AI 校验区两栏结构，左侧为本次审核数据与筛选，右侧为审核结论、统一校验统计和异常事实。
  - 右侧抽屉：推理详情约 `440px`；异常项快速修改约 `500px`。

### 3.2 响应式适配

当前为桌面端原型演示，优先保证 1440px 以上宽屏展示。窄屏时保留横向滚动，避免表格字段挤压和重排。

## 4. 视觉规范

### 4.1 设计规范来源

**设计规范来源**：

- 用户规范 `/src/docs/业务页面设计规范.md`
- 用户提供的列表页、表单页和 AI 校验页截图参考
- 当前 UFSP2.0 工作台/首页类页面的合理分割线、弱边界布局原则

**说明**：列表和表格仍遵循业务页面规范中的 32px 控件、4px 圆角、紧凑表格、多级表头和分页规则；按钮遵循主按钮、二级按钮、三级按钮、危险按钮和文字操作的轻阴影边界规范。合理保留页签栏底线、目录/列表中线、表格自身网格线和校验页标题栏底线，不额外给工具栏、选择提示区、分页区增加贯穿分割线；AI 校验右侧内容区减少贯穿式分割线，改用白色整体底、无边框信息带、浅底分组、行距和文字层级组织信息，不使用明显蓝色外框、发光边界、大面积推理过程区块或卡片套卡片。

### 4.2 自定义设计要点

- 工作台账录入列表页去掉内容区面包屑和二级标题，首屏直接从状态页签、目录树和工具栏进入业务列表，避免重复标题和多余留白。
- 左侧功能菜单图标使用用户提供的 iconfont 下载 SVG 原件，放入 `src/prototypes/problem-library-function-list/icons/` 按页面作用域维护；代码只做 XML/DOCTYPE 清洗、统一容器、光学比例校准和 `currentColor` 状态适配，不再由 Agent 自绘图标路径，也不使用 lucide / Ant Design 等现成代码图标库作为菜单主图标。
- 菜单图标语义与业务节点一一对应：工作台入口使用 iconfont “合_18工作台”，工作台账管理使用“记账本”，工作台账录入使用“编辑”，工作台账审核使用“校验”，工作台账上报使用“送审 提交”，整改督办管理使用“提醒”，整改下发管理使用“分发”，整改情况审核使用“通过”，整改明细查询使用“搜索”。
- 左侧菜单图标统一使用 `30px` 图标容器，折叠态使用 `32px` 图标容器；下载 SVG 因 `viewBox`、源文件留白和线面占比不同，按图标建立视觉缩放参数，使“编辑 / 校验 / 送审提交 / 分发 / 提醒 / 通过 / 搜索”等图标在菜单中保持同一视觉面积。
- 左侧功能菜单统一采用列表页标准：一级父级与一级无子菜单节点同为 `44px` 导航行，使用相同图标槽、文本起点、箭头位置和 `4px` 圆角；二级节点只通过 `24px` 左缩进表达从属，不再让父级标题变成另一套分组样式。
- 左侧菜单配色必须沿用顶栏深蓝体系：以 `#2A487E / #4A6FA8` 为品牌来源，选中态使用低饱和蓝灰行面、深蓝文字和半透明深蓝图标底，不使用亮蓝、左侧粗状态线、渐变行面或深蓝实心图标容器；父级展开时仅作为归属态，不加粗、不使用选中底色；当某个二级节点处于选中状态且父级收起时，选中反馈才转移到父级行，保证用户仍能判断当前位置。
- 左侧标题区的模块 logo 是身份标识，不是菜单项；不得使用边框、浅底图标盒或与菜单项相同的图标槽，只保留顶栏同源深蓝线性图标与标题文字，避免把标题区误读成可选菜单。
- 左侧菜单收起/展开控制属于标题区操作，展开态放在标题右侧，折叠态放在图标列顶部，不再放在侧栏底部空白区。
- 非选中态保持同尺寸浅底图标容器，菜单整体折叠态保持紧凑 `44px` 图标按钮，避免当前项因为容器尺寸或 SVG 原始画布差异显得突兀放大。
- 状态页签位于目录树和右侧列表的上一层级，避免只控制右侧列表而削弱页签优先级。
- 左侧年度/主题目录不使用硬边框卡片，但保留树与表格之间的浅蓝中线和收起把手，贴近规范截图的目录层级。
- 工具栏、选择提示区、分页区不再使用整条分割线，页面层级由 32px 控件、表格区域、页签底线、目录中线和分页控件自身边界承担。
- 顶部操作区按组件规范分级：录入和提交校验为主按钮；导入、导出、批量设置、查询方案为二级按钮；查询为主色图标按钮；刷新、筛选、列设置为二级图标按钮；删除为危险图标按钮。
- 顶部工具栏图标同样使用用户提供的 iconfont 下载 SVG 原件：录入使用“添加 新增”，提交校验使用“送审 提交”，导入/导出使用对应语义图标，删除使用“删除”，查询使用“搜索”，刷新使用“刷新”，筛选使用“筛选”，列设置使用“设置”；按钮内图标使用固定 `14px × 14px` 规格框，若 SVG 为长方形则按 `viewBox` 等比适配，最长边为 `14px`，不套用左侧菜单的光学校准缩放；工具栏控件高度统一 `32px`、圆角 `4px`。
- 审核列表工具栏继承同一套图标规则：审核使用“校验”，废除使用“废除”，销号使用“销号:完结”，导出、查询、刷新、筛选和列设置沿用同名 iconfont SVG，避免列表工具栏与左侧菜单出现两套图标风格。
- 分页使用居中简版样式，当前页为 `#6A8DC4` 填充，条数选择器为白底轻阴影。
- AI 校验工作区采用全页面新增/编辑样式：64px 白底标题操作栏、左侧返回图标、右侧集中放置校验页自身操作；去掉与本页业务无关的“保存”和“目录”。
- 工作台账审核列表沿用录入列表密度和表格结构；列表顶部“审核”只负责进入审核校验工作区，最终结果动作在校验页顶部拆成“通过 / 退回”，避免列表页绕过校验结论直接处理。
- 审核校验工作区沿用白色整体底、无边框信息带和浅底分组。结论区与录入校验页保持一致，展示“异常事实 / 合规性问题 / 一致性问题”三项统计，避免产生两套校验口径。
- 审核数据状态口径保持克制：页面和左侧筛选只显示“全部一致 / 存在异常”；内容不匹配、未找到证据、无法判断只在事实行作为异常结果标签展示。
- 审核异常明细的事实行展示录入原文、佐证附件或审核依据、判断原因；事实行只展示录入岗是否标记不认可，不展示“无异常 / 已递交说明 / 未递交说明”等说明状态，也不提供“查看依据 / 填写意见 / 审核建议”等动作。
- “不认可说明”是录入岗材料入口，“审核说明”是审核岗留痕入口，二者都放在“审核异常明细”标题区并跟随左侧当前选中数据展示；审核说明抽屉先只读展示前序审核岗累计说明，再提供本岗审核说明和证明截图，不混入录入岗材料或额外分类项。
- 审核页顶部按钮为“通过 / 退回”。“通过”在全部一致时直接完成；存在异常时只打开风险确认弹窗，不承载填写说明。 “退回”不再弹逐条填写说明弹窗，直接流转；退回原因优先取当前数据已保存的审核说明，未填写时使用系统异常摘要。
- 批量提交与单条提交保持同类页面延伸：页面模式由列表选择条数决定，只改变左侧项目数量和统计口径，不改变右侧结论、明细和处理动作的组织方式。
- 左侧不再使用项目卡片列表，改成整行数据快照表；默认全选，取消勾选后提交范围随之变化，异常明细只跟随当前选中的具体数据展示。快照表不展示原表序号，只展示带入顺序号；业务字段列紧凑排布，长文本默认省略并通过悬停展示完整内容，校验结果列固定在右侧。
- 顶部不再展示“批量提交”标签和四类结果切换，页面级结论只保留“全部一致 / 存在异常”，减少误导。
- AI 校验结论区改为“校验报告摘要”：左侧展示项目级结论和当前项目上下文，右侧展示异常事实、合规性问题、一致性问题三项统计；校验工作区使用白色整体底和无边框信息带，统计、项目行和事实行都不得做成孤立卡片，避免同一个状态重复显示，也避免多层卡片嵌套。
- AI 推理过程不作为主内容展示，默认只保留一行摘要和“推理过程”入口，完整过程放入右侧抽屉。
- 左侧概览不展示“本次提交校验”“多条提交”“从列表带入”等说明性小字，只保留“全部数据 / 全部一致 / 存在异常”三项筛选；点击筛选后左侧项目列表同步过滤，若当前选中项目不在筛选结果中，自动切换到第一条匹配项目。
- AI 校验结论区只做问题概览，不占用大面积说明空间；保留结论标题、当前项目、字段/事实数量和紧凑统计，具体判断原因下沉到异常明细。
- 异常项明细标题区横向组织：标题、简短说明和需复核数量放在同一行，避免在右侧宽屏空间充足时继续纵向堆叠。
- 左侧选中项目和右侧异常字段不使用贯穿高度的蓝色竖线；用圆角浅底、文字权重和状态文案表达选中与分组。
- 顶部右侧集中放置“刷新状态 / 推理过程 / 提交”，页面底部不再放重复操作栏；“处理异常项”不放在顶部，异常处理统一收口到当前数据级操作。
- 异常项明细标题区只提供“修改”入口，进入原系统风格的“工作台账录入 / 编辑”全页表单；字段和事实行只展示比对依据，不承载保存入口。
- 异常项支持整改措施、问题描述等富文本字段对比，按“字段名称与字段结论 / 多条待核验事实 / 录入原文 / 佐证附件 / 附件原文 / 不一致类型 / 判断原因 / 修改建议”的层级展示；富文本必须先完整拆解关键事实，再逐条匹配证据；明细采用无边框行分隔、浅底分组和圆角行面，不使用两个大段文本框并排堆放，也不把每条事实做成独立卡片或尖锐直角块。
- 当前数据级操作按钮使用 30-32px 高度、足够横向留白和 8px 左右圆角，避免小按钮大字、留白不足；保存后进入异步校验状态，由“刷新状态”查看结果。
- 列表页进入校验的按钮叫“提交校验”，避免误解为直接提交；校验页主按钮始终叫“提交”。当当前勾选范围仍有异常时弹出风险确认，说明“建议修改或补充不认可说明，若确认不影响流转可仍然提交”。不认可说明入口前置到当前数据级抽屉，支持文本和多张截图，均不强制填写。弹窗只保留“取消 / 仍然提交”，不再提供“去处理异常”或逐条填写说明列表。
- 页面级结果通过状态色区分：全部一致为绿色，存在异常为红色；字段级异常再细分内容不匹配、未找到证据、无法判断。

### 4.3 组件状态

- **默认态**：白色面板、弱边框、32px 控件。
- **悬停态**：菜单、表格行和按钮使用浅灰或蓝色文字反馈。
- **选中态**：左侧菜单展开态使用顶栏同源的低饱和蓝灰底、深蓝文字、半透明深蓝图标底和加粗文字，不使用左侧粗状态线；父级展开时只用深蓝文字提示当前分组，不加粗、不使用选中底色；父级收起且含当前二级节点时整行进入选中态；折叠态使用紧凑图标反馈；页签使用蓝色文字和底部线；表格行使用浅蓝底。
- **加载态**：点击提交后展示居中浮层和旋转图标，提交按钮置灰。
- **异常态**：AI 异常项使用状态色、结构化字段对比和轻边界操作按钮，避免大面积黄色铺底造成噪声。
