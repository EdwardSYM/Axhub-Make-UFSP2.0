# 案例库（AI改造）原型规格

## 1. 业务与功能

### 1.1 核心目标

本页面用于搭建“案例库（AI改造）”的独立原型框架，并完成“一般案例管理”的第一版前端静态原型。一般案例管理用于统一处理日常监督形成、专项监督形成、上级下发、外部公开案例和其他来源形成的一般案例。

页面只做前端静态演示：不接入后台接口、数据库、真实 AI 能力、权限校验或真实业务公式。

### 1.2 功能清单

- **独立原型入口**：新增 `src/prototypes/case-library-ai`，页面名称为“案例库（AI改造）”，并在页面树“案例库（AI改造）”文件夹下挂载“一般案例管理”入口。
- **左侧功能菜单**：统一复用 `src/components/case-library-feature-menu`；包含案例检索、一般案例管理、案例聚类分析、典型案例管理、案例采集管理和案例标签管理，支持分组展开/收起和整体菜单收起/展开。典型案例管理下设“申请、审核”两个二级菜单，生命周期状态和案例类型不作为左侧子菜单。
- **一般案例管理主页面**：包含待入库、已入库、不入库、已停用、全部五个生命周期页签，按“工作台账录入”列表页标准组织左侧目录、页面级工具栏、查询筛选、选择提示、案例列表和分页；页面不再展示独立面包屑、页面标题、说明块或概览指标条。
- **待入库案例处理页**：点击待入库列表“处理”进入独立处理视图，按照一般案例字段展示基本信息、关联来源、案例内容、标签信息和材料附件，并在表单下方直接展示来源详情和相似案例列表；不再使用辅助信息页签。
- **详情与编辑页**：已入库、不入库和已停用案例支持查看详情、进入编辑、调整标签、查看相似案例、查看来源详情和操作记录。
- **案例聚类分析页**：基于已入库的一般案例，按年度、来源类型和区划选定分析范围，关键词和标签收口到“更多筛选”；页面聚焦聚类覆盖、共性问题列表、关联案例调整和典型案例申请，支撑“回头看、举一反三”。
- **典型案例管理页**：拆分为“申请”和“审核”两个完整列表页；申请页承接聚类分析和一般案例加工形成的典型案例申请，状态收口为待提交、被退回、已发布、全部；审核页承接已提交申请，完成审核通过、退回和发布记录查看；一个典型案例可以关联多个已入库一般案例。
- **辅助弹窗/抽屉**：实现导入、标签选择、不入库确认、停用确认、来源详情、相似案例对比和入库记录查看；待入库处理页的来源详情和相似案例直接在正文区块展示，滚动查看；新增直接进入全页面新增/编辑表单，不再弹出新增方式选择。
- **URL 状态**：使用 `feature` 参数记录当前功能节点，便于后续逐页深化。
- **Axure 变量**：暴露当前 `feature_key` 和 `feature_name`。

### 1.3 当前菜单结构

```text
案例库
├── 案例检索
├── 一般案例管理
├── 案例聚类分析
├── 典型案例管理
│   ├── 申请
│   └── 审核
├── 案例采集管理
└── 案例标签管理
```

说明：待入库、已入库、不入库、已停用属于一般案例生命周期状态，放在“一般案例管理”页面内部作为页签或筛选；典型案例“申请、审核”是办理角色不同的二级功能；问责类典型案例、共性问题案例属于典型案例类型，放在申请页和审核页内部作为类型维度。

### 1.4 交互要点

- 点击“案例检索”进入独立原型 `/prototypes/gansu-case-search`；点击其他叶子功能节点进入案例库主原型的对应 `feature` 页面。
- 点击分组标题：展开或收起该分组下的子功能。
- 点击标题区收起按钮：左侧菜单压缩为仅图标状态；再次点击恢复展开。
- 默认进入“一般案例管理”。

## 3. 布局与结构

- **布局模式**：顶部全局导航 + 左侧案例库功能菜单 + 右侧内容占位区。
- **页面宽度**：沿用项目 `max-width: 1920px` 工作台框架。
- **左侧菜单**：展开宽度 `272px`，收起宽度 `64px`。
- **右侧内容区**：白色整体底，主页面采用“页签栏 > 左侧目录 + 右侧列表”的工作台账录入页结构；右侧列表内部采用“工具栏/查询 > 高级筛选 > 选择提示 > 表格 > 分页”。一般案例新增/编辑页保持全页面四列表单标准，先选择来源类型，再动态维护来源信息，最后整理统一案例内容；录入控件尺寸与待入库处理页的产品化表单标准一致；待入库处理页采用标准全页面表单头、左侧三列表单、右侧 AI 入库概览，来源详情和相似案例作为表单正文下方的连续区块，不使用页签切换。案例聚类分析页采用“顶部筛选 + 五项核心指标 + 共性问题列表 + 详情抽屉”的工作台结构，优先让用户判断案例总量、聚类覆盖、未聚类数据入口和共性问题覆盖案例数，不常驻复杂报表或左右分栏详情。典型案例申请页和审核页均采用“状态页签 + 左侧类型目录 + 右侧台账列表”的标准业务列表结构，不在列表页常驻右侧详情面板；申请、审核、发布相关字段进入独立详情页。
- **桌面优先**：优先保证 1440px 以上桌面端原型展示。

### 3.2 典型案例特殊字段

典型案例不是一般案例的状态标签，而是加工后的成果资产；字段应承接问题库、案例聚类分析、辖区/本级分析和首页发布场景。

| 字段 | 原型处理 |
| --- | --- |
| 典型案例编号 | 保存后生成，列表和详情展示 |
| 典型案例标题 | 加工后的发布标题，不直接等同一般案例标题 |
| 典型案例类型 | 共性问题案例、问责类典型案例、整改成效案例 |
| 状态 | 申请页展示待提交、被退回、已发布、全部；审核页展示待审核、被退回、已发布、全部 |
| 案例领域 | 用于首页发布、监督分析和评价口径引用 |
| 关联一般案例 | 多选集合，一个典型案例可关联多个已入库一般案例；列表展示关联数量和首条一般案例，详情页展示完整集合 |
| 关联问题 | 可关联已销号问题或专项监督问题，用于问题库“案例沉淀分析” |
| 来源聚类分析 | 来自案例聚类分析时记录共性问题类型和分析结论 |
| 代表性说明 | 说明为什么具备代表性，解决“共性案例代表性不足”问题 |
| 案例摘要 | 对外发布或内部学习使用的加工文本 |
| 以案促改价值 | 支撑整改复盘、回头看、举一反三和治理提升 |
| 适用场景 | 首页展示、辖区分析、专项评价、问责通报、培训学习等 |
| 问责信息 | 问责类典型案例需要记录问责处理或移送情况 |
| 制度完善 | 整改后形成的制度、规则、流程或校验项 |
| 审核意见 | 审核通过、退回原因或发布前修改意见 |
| 材料附件 | 发布摘要、佐证材料、同类案例清单、问责处理记录等 |

补充规则：

- 新增页不单独做来源选择页面，仍进入当前新增页；新增进入时默认选择“日常监督形成”，来源类型只保留“日常监督形成、专项监督形成、上级下发、外部公开案例、其他来源”。
- 一般案例列表不再单独维护处理状态；列表列、筛选项、概览文案和 mock 数据必须同步使用顶部生命周期页签口径“待入库、已入库、不入库、已停用”。
- 日常监督形成、专项监督形成都需要选择具体关联问题；关联问题数量较多，表单内不使用单一下拉框，改为打开右侧抽屉，通过问题编号、标题、单位、地区检索并从列表中选择。
- 案例标签不使用普通文本输入框或原生单选下拉；使用自定义多选下拉，点击后在下拉层内平铺展示全部可选标签，点击标签可选中或取消，已选标签继续在当前字段下方平铺展示并可点击移除。未选择时展示若干常用标签示例，便于快速点选。
- 选择“关联问题”后，静态模拟自动带入标题、地区、发生时间、涉及主体、案例描述等通用案例字段，用户可继续整理修改。
- 爬虫采集进入页面的外部公开案例，可自动带入发布机构或来源网站、原文链接、发布时间。
- “来源名称、来源说明”只用于“其他来源”，不作为所有来源的通用字段。

## 4. 视觉规范

- 继承财会监督 V2.0 原型的白色整体底、弱分隔线和浅蓝选中态。
- 菜单采用列表页左侧菜单标准：一级父级与一级无子菜单节点同为 `44px` 导航行，使用相同图标槽、文本起点、箭头位置和 `4px` 圆角；二级节点只通过 `24px` 左缩进表达从属。
- 菜单配色沿用顶栏深蓝体系：以 `#2A487E / #4A6FA8` 为品牌来源，选中态使用低饱和蓝灰行面、深蓝文字、半透明深蓝图标底和加粗文字，不使用亮蓝、左侧粗状态线、渐变行面或深蓝实心图标底；父级展开时只作为归属态，不加粗、不使用选中底色；当某个二级节点处于选中状态且父级收起时，选中反馈才转移到父级行。
- 标题区模块 logo 是身份标识，不是菜单项；不得使用边框、浅底图标盒或与菜单项相同的图标槽，只保留顶栏同源深蓝线性图标与标题文字。
- 收起/展开控制属于标题区操作，展开态放在标题右侧，折叠态放在图标列顶部，不再放在侧栏底部空白区。
- 一般案例管理主页面以问题库（AI改造）“工作台账录入”页面为结构基准：复用 `ufsp-ledger-frame / ufsp-ledger-tabs / ufsp-ledger-content / ufsp-ledger-tree / ufsp-ledger-toolbar / ufsp-ledger-table / ufsp-pagination` 的布局节奏。
- 页签栏高度 `48px`，工具栏控件 `32px`，圆角 `4px`，按钮使用轻阴影；不展示重复的面包屑、页面标题、说明块、统计卡片或概览指标条。
- 顶部工具栏按标准页组件组织：左侧只放页面级动作“新增、导入、导出、入库”；不放“处理概览”“批量处理”或无明确语义的危险 X 图标动作。
- 列表页新增按钮文案固定为“新增”，不得写成“手工新增”；导入、导出和新增图标复用问题库已确认的 `action-import / action-export / action-add` iconfont 原件，统一 `14px` 尺寸、`6px` 图标文字间距。
- 列表页“入库”按钮使用蓝色描边二级按钮，文字、边框和图标继承同一蓝色；图标使用通过/确认语义的 `pass.svg`，不使用文件发送类图标。
- 右侧查询组件为固定组件组合，必须与工作台账录入页完全一致：`ufsp-search-box ufsp-filter-input` 输入框 + `ufsp-icon-btn ufsp-icon-btn-primary` 查询 + `ufsp-icon-btn ufsp-icon-btn-secondary` 刷新 + `ufsp-icon-btn ufsp-icon-btn-secondary` 筛选 + `ufsp-btn ufsp-btn-secondary` 查询方案 + `ufsp-icon-btn ufsp-icon-btn-secondary` 列设置；图标统一 `14px`。
- 表格使用业务规范表头：`#6A8DC4` 背景、白色表头文字、32px 行高、`#E4E4E4` 网格线、表头左右 `4px` 圆角、行悬停 `#F6F6F6`；勾选列和案例标题列左侧冻结，操作列右侧冻结。
- 待入库列表字段按当前治理动作收口为“选择、案例标题、来源类型、入库状态、导入时间、操作”；“来源类型”列只展示与左侧目录、表单下拉一致的来源类型分类，不展示来源编号、来源单位、文件名、外部地址等原始信息；不再展示“业务分类、标签状态、数据质量、疑似重复”列。
- 左侧目录按“年度 + 来源类型”组织，来源类型固定为“日常监督形成、专项监督形成、上级下发、外部公开案例、其他来源”，并与新增/编辑下拉、列表来源类型列和筛选项共用同一口径；点击来源类型筛选当前生命周期页签内数据。
- 来源详情采用可落地的数据结构：关联来源按来源类型展示联动字段；`sourceRawText` 合并展示原始说明、来源单位、原始标题、导入时间等文本信息；`sourceAttachments` 有值时展示材料附件入口；`sourceUrl` 有值时展示外部地址。
- 表格横向滚动容器使用外边距控制与页面边缘的距离，不在滚动容器内部加左右 `padding`；冻结列必须在滚动容器内裁切，避免拖拽滚动后穿透到表格外侧留白。
- 处理页头部复用 `ufsp-form-head / ufsp-form-title / ufsp-form-actions` 标准；按钮按优先级从左到右排列，主流程“确认入库”为主按钮，保存位于主按钮左侧并使用蓝色描边二级按钮。
- 处理页表单复用 `ufsp-ledger-edit-section / ufsp-ledger-form-grid / ufsp-field-block`，左侧表单使用三列布局，按“基本信息、关联来源、案例内容、标签信息、材料附件、来源详情、相似案例”组织，长文本整行展示，右侧独立保留一列作为 AI 入库概览；来源详情和相似案例不得做成页签按钮，用户通过页面滚动查看。
- 一般案例新增/编辑页保持全页面四列字段栅格：头部复用 `ufsp-form-head / ufsp-form-title / ufsp-form-actions`，纯新增/编辑态只保留当前主操作“保存”；表单主体按“来源选择、来源信息、案例信息、材料附件、系统信息”组织，不复用详情页摘要、详情页签或使用统计卡片。
- 一般案例新增/编辑页的录入框与处理页保持同一产品化控件标准：标签约 `13px`，控件高 `32px`，`4px` 圆角和轻量阴影；字段仍按四列排布，长文本整行展示并保留字数提示。
- 一般案例新增/编辑页的“案例标签”字段使用 32px 高度触发器承载多选入口；下拉层紧贴字段展开，标签以紧凑胶囊按钮平铺，已选态使用浅蓝底和勾选标识，不使用系统原生 `select`。
- 来源类型切换时保留案例标题、所属地区、发生时间、涉及主体、案例描述、案例标签、备注等通用字段；清空原来源对应的专属字段；如果当前来源专属字段已有填写，切换前提示“切换来源类型将清空当前来源信息，是否继续？”；案例正式入库后，编辑态不允许直接修改来源类型。
- 材料附件为固定组件：标题使用左侧蓝色短竖线；上方表格使用 `#6A8DC4` 表头、白色表头文字、`4px` 圆角、文件名称 / 文件大小 / 上传时间 / 操作列；空状态展示“暂无数据”；下方上传条展示上传入口、大小/扩展名说明和红色非涉密系统保密提示。详情页使用同一表格的只读态，不展示上传条。
- 案例聚类分析页定位为“筛选案例、识别共性、查看同类案例、确认分析结果并可发起典型案例”：页面不再展示面包屑标题块、左侧大筛选栏、五步流程条、趋势图或复杂报表；筛选收口到顶部，首屏展示一般案例总数、已聚类案例、聚类案例覆盖率、未聚类数据和共性问题数五项指标，再展示按处理状态页签筛选的统一共性问题列表。
- 案例聚类分析顶部筛选和四项指标参考全景分析的视觉节奏：筛选区使用浅底紧凑条件栏，指标区使用轻量信息带和低强度色彩提示；“已聚类案例”通过覆盖率进度线表达聚类覆盖情况，不使用厚重统计卡或大面积图表。
- 案例聚类分析列表区不强行撑满整屏高度，按内容自然收口；列表工具行只保留标题、处理状态页签筛选和导出操作，去掉当前范围和排序说明，减少噪声并充分利用页面宽度；共性问题表格采用扁平工作台样式，不再叠加外层卡片和滚动容器边框，只保留必要行分隔；处理状态页签参考首页小胶囊选中态，使用浅蓝灰底槽、白底轻阴影选中项和深蓝文字，避免厚重描边块影响判断效率。
- 案例聚类分析页不再设置“案例检索分析”父级和“案例检索 / 共性洞察”下级菜单；左侧菜单只保留一级功能“案例聚类分析”，直接进入当前分析页面。
- 案例聚类分析页负责分析一批案例的共同规律并确认结果；典型案例管理负责对有代表性的分析结果进行加工、审核和发布。聚类页中的“确认聚类”必须落到当前共性问题上，不做全页面泛确认。
- 案例聚类分析页必须显性解决“什么算共性案例、共性案例判断维度不明确”的问题：主列表不单独展示整块判定口径，只在共性问题名称下展示简短判定依据；完整判定维度和方法进入详情抽屉，判定维度包括问题表现、形成原因、整改方式、预算环节和资金类型，判定方法采用 AI 初分后按同类问题链和关联案例集合进行人工确认。
- 案例聚类分析页必须显性解决“沉淀共性案例代表性不强”的问题：每个共性问题在详情抽屉内展示代表性评估、代表性原因和补强建议；代表性不足的共性问题不能直接进入典型案例申请，应先调整关联案例或完成代表性确认。
- 案例聚类分析 mock 数据覆盖不同问题类型和业务场景：专项债券绩效目标、政府采购履约资料、财政暂付款清理、惠民补贴重复发放、行政事业单位资产处置、预算项目入库论证、部门决算公开、财政资金支付内控和整改销号佐证材料等，保证列表、页签筛选和详情抽屉能呈现多类型聚类结果。
- “已聚类案例”指标按一般案例去重统计，一个一般案例即使关联多个共性问题也只计算一次；该卡片只解释已聚类案例口径，不再重复展示未聚类数量和覆盖率，也不使用进度条，避免与新增指标重复。
- “聚类案例覆盖率”独立展示当前筛选范围内已聚类案例占一般案例总数的比例；“未聚类数据”独立展示暂未关联共性问题的一般案例数量，并作为入口打开右侧抽屉，查看未聚类一般案例列表、未聚类原因和建议处理动作。暂不展示同比、环比或增长率，避免将重新分析、人工拆分合并造成的数量变化误读为趋势。
- 案例聚类分析顶部筛选只保留年度、来源类型和区划。年度按一般案例发生年度筛选，缺失发生时间归入“时间不详”；来源类型与一般案例管理保持一致，包含日常监督形成、专项监督形成、上级下发、外部公开案例和其他来源；区划缺失归入“区划不详”，不能直接排除。关键词、标签、预算环节和资金类型进入“更多筛选”，用于体现 AI 对问题与案例按预算编制、预算执行、决算、绩效评价、整改落实和资金类型等维度打标分析。
- 共性问题列表默认按关联一般案例数从高到低排列，上方提供“全部、待确认、已确认、已申请典型、已形成典型”状态页签，帮助用户快速聚焦待人工确认和已转典型案例的共性问题；表格只展示共性问题名称、关联案例数、主要特征、来源构成、处理状态和操作，并在共性问题名称下显示简短判定依据，不在主列表展示风险等级、复现度、匹配度等尚无明确计算口径的指标。
- 点击共性问题打开右侧抽屉，抽屉展示共性问题名称、说明、处理状态、关联案例数量、来源构成、预算环节、资金类型、业务维度、共性判定标准与方法、代表性评估、反复出现的问题表现、常见形成原因、常见整改方式、高频标签和关联一般案例列表。
- 关联一般案例集合允许人工调整；抽屉内展示案例标题、来源类型、区划/单位、主要标签和查看/移除操作；“新增关联案例”打开大尺寸弹窗，通过搜索和勾选已入库一般案例进行补充。
- 案例聚类分析页支持从当前共性问题直接申请典型案例：申请后模拟进入典型案例申报，并自动带入共性问题名称、共性问题说明、共性特征和已关联一般案例。
- 当前共性问题至少关联 1 条一般案例后才允许提交典型案例申请；如果用户移除到 0 条，前端只提示先补充关联案例。
- 典型案例管理不重复做共性识别，也不替代一般案例管理；“申请”处理填报侧的新增、从聚类分析生成、保存、提交、退回修改和发布记录查看；“审核”处理审核侧的审核通过、退回和发布记录查看。列表页必须遵循标准业务页：状态页签跨越类型目录和列表，左侧目录可收起，右侧工具栏使用固定查询组件组合，表格使用冻结选择列、典型案例标题列和操作列，底部使用简版分页。已发布典型案例可被首页案例栏目、辖区/本级分析“案例沉淀数”、专项监督评价“典型案例转化率/问责落实率”等模块引用。
- 典型案例列表不展示“生成来源”维度，也不按来源切分；列表字段收口为“选择、典型案例标题、类型、案例领域、关联一般案例、状态、更新时间、操作”。典型案例的申请字段、代表性说明、关联一般案例、以案促改价值、问责/制度完善信息和审核材料不得常驻在列表右侧挤压表格；点击“编辑 / 审核”后进入独立详情页，详情页复用 `ufsp-form-head / ufsp-form-title / ufsp-form-actions` 和分组字段结构。
- 分页使用业务规范简版居中分页：`共 X 条 / 上一页 / 当前页 / 下一页 / 20 条/页`，当前页使用 `#6A8DC4` 填充，不使用深蓝或卡片式分页。
- 表格操作列按标准页文字操作样式展示；标签默认展示 3 个，其余显示 `+N`；AI 生成内容统一使用“AI建议”徽标；人工确认内容使用“已确认”状态。
- 阻断、提醒、正常分别使用红、黄、绿状态色；处理页中阻断项不做真实后端限制，只做前端状态表达。
- 图标只用于识别菜单语义，不做装饰性堆叠。

## 5. 前端交互与模拟逻辑

- 点击左侧目录：按年度或来源类型筛选当前生命周期页签内案例。
- 点击待入库列表“处理”：进入待入库案例处理页。
- 点击已入库列表“详情 / 编辑”：进入详情或编辑视图。
- 待入库处理页不通过页签或抽屉查看辅助信息；来源详情和相似案例直接作为正文区块展示，用户滚动查看。
- 列表和详情页点击“来源详情 / 查看相似案例 / 入库记录”：打开右侧抽屉；来源详情展示来源类型、关联来源、原始信息文本，并按数据有无展示材料附件和外部地址。
- 点击“新增”：直接进入一般案例新增/编辑全页面表单。
- 点击“导入”：打开导入弹窗，模拟模板下载、文件上传和导入结果。
- 点击“标签选择”：打开标签选择弹窗，展示分类树、标签列表和已选标签。
- 点击“不入库 / 停用”：打开确认弹窗，模拟填写原因和确认动作；在“不入库”页签点击“恢复待入库”模拟将案例恢复到待入库状态。
- 点击 AI 字段建议“采用”：前端标记为“已采用”，不覆盖真实数据。
- 入库、刷新等操作只做前端提示，不写入后端。
- 点击“案例聚类分析”菜单：进入案例聚类分析页。
- 点击案例聚类分析顶部年度、来源类型和区划：静态更新当前分析范围文案；点击“更多筛选”展开关键词、标签、预算环节和资金类型筛选。
- 点击“刷新”：模拟按当前范围刷新聚类分析结果，并给出页面提示。
- 点击共性问题列表上方状态页签：按全部、待确认、已确认、已申请典型和已形成典型筛选当前共性问题列表，页签数量随人工确认和典型案例申请状态静态变化。
- 点击共性问题列表行或“查看详情”：打开右侧抽屉，查看共性说明、共性特征、来源构成和关联一般案例集合。
- 点击“新增关联案例”或“调整关联案例”：打开大尺寸弹窗，通过检索和勾选人工增删当前共性问题关联的一般案例。
- 点击“确认分析结果”：将当前共性问题标记为已确认。
- 点击“申请典型案例”：在当前共性问题至少关联 1 条一般案例且代表性不为“需补充样本”时，模拟进入典型案例申报并带入共性问题名称、说明、特征和关联案例；如果代表性不足，前端提示先补充关联案例或完成代表性确认；已申请后提供进入典型案例管理的入口。
- 点击“典型案例管理 / 申请”菜单：进入典型案例申请页。
- 点击“典型案例管理 / 审核”菜单：进入典型案例审核页。
- 点击典型案例申请页状态页签：按待提交、被退回、已发布、全部筛选。
- 点击典型案例审核页状态页签：按待审核、被退回、已发布、全部筛选。
- 点击类型目录：按共性问题案例、问责类典型案例、整改成效案例筛选。
- 点击典型案例申请列表行或“编辑”：进入独立申请详情页，展示典型案例标题、案例领域、代表性说明、关联一般案例、以案促改价值、问责/制度完善信息和审核材料。
- 点击典型案例审核列表行或“审核”：进入独立审核详情页，展示同一套典型案例信息和审核意见。
- 点击“从聚类分析生成 / 新增 / 提交 / 审核通过 / 退回”：仅做前端提示，不接入真实审核流、权限流或发布服务。
