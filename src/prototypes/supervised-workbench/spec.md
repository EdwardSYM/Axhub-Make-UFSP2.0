# 被监督者工作台规格文档

## 1. 概述

当前版本面向被监督单位的日常办理视角：顶部看当前主题下有哪些功能入口，中间左侧看办理概览四类维度，中间右侧看待办明细，底部办理辅助区承接筛选联动提供处理建议和支撑材料。

## 2. 变更记录

- 修复页面样式依赖：移除已不存在的 `ufsp-sky` 主题 CSS 引用，页面样式统一由本目录 `style.css` 承载。
- 本次调整将底部"智能辅助分析"重构为"办理辅助区"，从固定四块内容改为"左建议 + 右支撑"两栏联动布局。
- 底部不再叫"智能辅助分析"，改成更贴近使用场景的"办理辅助区"。
- 底部只做一种联动逻辑：上面选了什么，下面围绕这个对象给处理帮助。
- 按钮统一为三类：办理类（去补正/去提交/去更新）、查看类（查看退回原因/查看材料清单等）、筛选类。

## 3. 页面结构

- 顶部：全局导航、页面标题、更新时间和监督流程入口卡片。
- 中间左侧：办理概览，2×2 四象限布局展示待办事项、阻塞流程、风险数据、已办跟踪。
- 中间右侧：待办事项列表，承接左侧办理概览的筛选联动。
- 底部：办理辅助区，"左建议 + 右支撑"两栏布局，随上方筛选联动切换内容。
- 弹层：业务全流程视图，支持悬停查看节点说明并点击进入对应功能页。

## 4. 办理概览

### 4.1 模块定位

办理概览从被监督者办理视角拆分四类维度：待办事项、阻塞流程、风险数据、已办跟踪。模块标题在页面上使用"办理概览"，不再展示"当前需响应 X 项 · 已提交事项跟踪 X 项"这类副标题统计。

模块回答四个主问题：

- 待办事项：我现在有哪些事要处理。
- 阻塞流程：哪些事项当前卡住或容易被退回。
- 风险数据：哪些事项风险更高。
- 已办跟踪：我处理过但流程还没结束的事项现在走到哪。

中间左侧不做原因分析、不做整改建议、不做规则解释、不做案例推荐。这些内容放到底部办理辅助区或事项详情页。

### 4.2 子板块标题样式规范

办理概览下的四个子板块采用 2×2 等宽布局，第一行展示"待办事项 / 阻塞流程"，第二行展示"风险数据 / 已办跟踪"。四个子板块采用统一的标题行样式：

- 标题左侧统一带 3px 宽的小圆角色条，用于区分模块属性（蓝色=待办事项/已办跟踪，琥珀=阻塞流程，红色=风险数据）
- 标题文字与说明文字放在同一行，标题左、说明在标题右侧
- 数量或状态标签放在行最右侧
- 四个子板块统一使用相同的内边距和圆角，保持视觉和谐
- 子板块高度由 2×2 网格统一控制，内容不得撑开父容器；待办事项和阻塞流程内容较多时在子板块内部滚动查看。

### 4.3 卡片视觉规范

由于子板块支持内部滚动，卡片无需过于紧凑，以美观舒适为主：

- 子板块内边距：16px（p-4）
- 卡片网格间距：10px（gap-2.5）
- 卡片最小高度：56px，内边距 12px 水平 / 8px 垂直
- 卡片标题字号：12px 加粗，数量字号：18px 加粗
- 卡片副标题字号：11px，与标题间距 4px
- 标题行与卡片区域间距：12px（mb-3）
- 已办跟踪板块内分组标题与卡片的间距保持一致，整体视觉权重与其他三个子板块对等

### 4.4 当前重点提醒

当前重点提醒放在模块标题右侧，与"办理概览"形成同一视线层级。它把待办事项、阻塞流程、风险数据和已办跟踪结果转成一句行动提示，用于回答"今天最先看什么、为什么先办"。

### 4.5 当前需响应

当前需响应展示当前需要本单位直接操作的事项数量，按"用户要做的动作"拆分。不展开每个事项的业务主题，不展示总数拆分为各类状态，不展示截止时间。

### 4.6 优先处理依据

优先处理依据是动态模块，不固定写死为"时限优先级"。不同主题按可用字段选择展示方式，最多展示 3 项。展示被退回、已超期、已上传未提交、高风险等卡片，内容紧凑不散发。

### 4.7 经办事项进展

经办事项进展展示本单位已经处理过、提交过、补正过、更新过或上传过材料但尚未完全结束的事项的流转跟踪。展示内容：

- 流转节点：待审核、审核/复核中、待最终确认。
- 关注提醒：我关注事项、最长停留、最近反馈、7天未反馈。

"我关注事项"不是流程节点，不与前三个节点并列。前台统一使用"待最终确认"，悬浮或详情中说明"问题整改类为待销号，其他流程类为待完结"。已办跟踪不展示"被退回"和"已上传未提交"，避免和待办、阻塞重复。

## 5. 办理辅助区

### 5.1 模块定位

办理辅助区定位一句话：

> 上面告诉我"有哪些事、哪些卡住、哪些风险高"，这里告诉我"这类事怎么处理、需要补什么、可以参考什么"。

它承接上方办理概览的筛选结果，随当前筛选变化切换辅助内容，不再固定展示四块独立内容。不做原因分析、不做整改建议、不做规则解释、不做案例推荐。

### 5.2 布局

采用"左建议 + 右支撑"两栏紧凑布局：

- **左侧（60%）**："当前处理建议"，按当前辅助对象展示处理步骤和建议操作。
- **右侧（40%）**："处理支撑"，根据辅助对象展示具体支撑内容（退回原因、材料清单、风险依据、流程状态等），或展示四项支撑能力入口。

顶部显示"当前辅助对象：全部待办 / 被退回 / ..."标签。

### 5.3 联动规则

底部只做一种联动逻辑：**上面选了什么，下面围绕这个对象给处理帮助。**

| 用户操作 | 办理辅助区展示 |
|----------|--------------|
| 未选择任何筛选 | 展示全局处理建议 + 四项支撑能力入口 |
| 点击"被退回" | 展示退回处理步骤 + 退回原因与补正要求 |
| 点击"材料不完整" | 展示材料补全步骤 + 材料缺项与示例 |
| 点击"7天未更新" | 展示更新步骤 + 更新要求与流程影响 |
| 点击"高风险事项" | 展示风险处理步骤 + 风险依据与规则来源 |
| 点击右侧某条待办 | 展示该事项的专属处理建议 |

### 5.4 默认态（未选择筛选）

左侧"当前处理建议"展示四类全局建议：
1. 被退回事项 — 处理重点 + 去补正 / 查看退回原因
2. 已上传未提交事项 — 处理重点 + 去提交 / 开始自查
3. 7天未更新事项 — 处理重点 + 去更新 / 查看更新要求
4. 高风险事项 — 处理重点 + 去处理 / 查看风险依据

右侧"处理支撑"展示四项支撑能力入口（标题 + 一句说明，点击打开对应抽屉）：
- 退回原因与补正建议
- 提交前自查
- 历史同类整改参考
- 流程与反馈跟踪

### 5.5 选中某类事项后的展示

选中"被退回"后：
- 左侧展示四步处理建议：查看退回意见 → 补齐佐证材料 → 核对一致性 → 补正后重新提交
- 右侧展示退回原因详情：退回原因项（佐证材料不完整/附件与说明不一致）和补正建议列表

其他筛选类型同理，按对象特征展示对应的处理步骤和支撑详情。

### 5.6 按钮逻辑

只保留三类按钮：

| 按钮类型 | 示例 | 作用 |
|----------|------|------|
| 办理类 | 去补正、去提交、去更新 | 筛选右侧待办 + 打开对应抽屉 |
| 查看类 | 查看退回原因、查看材料清单、查看流程日志 | 打开对应抽屉 |

已删除：
- "查看需处理事项"按钮（与右侧待办明细重复）
- "辅助生成时间"展示

### 5.7 数据来源与边界

使用本页面本地模拟数据，展示文案带有事实来源或明确为参考，不使用无依据的 AI 结论。当前事项是主对象，退回说明、流程日志、历史同类整改是支撑信息。

## 6. 数据与交互

- 事项列表继续使用本目录 `index.tsx` 内的本地模拟数据。
- 时限状态以原型基准日期 `2026-03-26` 判断，保证临期、超期展示在静态原型中稳定。
- 左侧概览项点击后，右侧列表顶部展示"当前筛选：筛选条件 ×"，点击 × 可清除筛选。
- 右侧事项卡展示事项标题、截止日期、流程节点、模块、事项状态、事项分类、临期或超期标签和当前动作。
- 左侧用于整体判断，右侧用于查看具体事项并进入办理。
- 待办明细顶部不展示"全部 / 超期 / 临期 / 被退回"快捷切换，筛选入口统一收敛到左侧办理概览。
- "已完结事项"不在办理概览模块右上角展示；已完成、已销号、已归档事项不参与当前办理压力统计，如需查看通过明细查询进入。
- 底部办理辅助区复用同一套本地事项事实，点击后同样通过右侧列表展示具体事项。

## 7. 左右联动规则

- 点击"待办事项"下的统计项，右侧待办明细筛选对应事项。
- 点击"阻塞流程"下的被退回、已上传未提交、材料不完整、7天未更新等统计项，右侧待办明细筛选对应事项。
- 点击"风险数据"下的高风险事项、涉及金额较大、重复命中事项、待核实疑点，右侧待办明细筛选对应事项。
- 点击"已办跟踪"下的待审核、审核/复核中、待最终确认、我关注事项、最长停留、7天未反馈等入口，打开"已办跟踪列表"抽屉并按入口筛选，不联动右侧待办明细。
- 已办跟踪抽屉字段只保留：事项名称、我上次处理动作、我上次处理时间、当前节点、当前处理岗、停留天数、最近反馈、查看流程。
- 点击待办事项、阻塞流程、风险数据统计项不直接打开弹窗；只有已办跟踪节点、底部辅助入口和事项详情类入口打开抽屉。

## 8. 不展示内容

办理概览不展示：

- 历史闭环池。
- 已完成/已销号阶段卡。
- 独立退回补正概览大区。
- 完整办理流转情况。
- 临期/超期合并项。
- 4-7 日内到期卡片或首次处理类独立卡片。
- 标题下方"当前需响应 X 项 · 已提交事项跟踪 X 项"副标题。
- 模块内部单独占位的当前重点提醒横条。
- 右上角"已完结事项"按钮。
- 中间左侧的事项分类/应办事项分布大区。
- 百分比和占比条。
- AI 实时生成风险数据。
- 整改建议。
- 案例推荐。
- 规则触发解释。

已完结事项不参与当前办理压力统计，也不在办理概览模块首屏展示。

底部办理辅助区不展示：

- 风险事件数量汇总。
- 规则触发情况列表。
- 无来源的 AI 分析结论。
- 大段报告式说明。
- 顶部业务入口分类统计。
- 顶部来源切换按钮。
- 被监督者关注维度横条和概念化能力标签。

## 9. 空状态

当当前主题下没有事项时：

- 中间左侧统一展示"当前暂无待处理事项"。
- 右侧筛选后无匹配结果时，展示同一空状态文案，并提示可通过明细查询查看全部记录。
- 底部办理辅助区不留空白，改为展示"暂无退回""暂无跟踪""可提交前自检"等辅助性占位信息。

## 10. 独立维护约束

- 本页面为物理复制出的独立页面，不从 `topic-workbench2` import 或 re-export。
- 共享组件（如 `BreadcrumbNav`、`FlowNode`、`IndicatorCardContent`）在维护时需确认上游变更。
