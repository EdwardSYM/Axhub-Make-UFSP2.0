# V1 提示词配置

## 1. 业务与功能

### 1.1 页面定位

面向项目实施人员，在不同业务主题下维护、复制、启用和查看提示词配置。V1 弱化“版本管理”概念，聚焦“当前主题配置什么、正在使用哪一条、如何新增或调整”。

### 1.2 功能范围

- 业务分类树：固定两级分类，选择具体业务主题后展示该主题下的全部配置。
- 配置列表：展示版本号、更新时间、更新人、变更说明、启停状态和操作。
- 新增配置：直接进入新增页，系统自动生成下一个版本号；不再弹出创建方式选择。
- 配置详情：与新增、编辑页使用同一信息结构，全部只读，并补充追溯信息。
- 编辑配置：
  - 停用配置直接修改并保存当前记录。
  - 启用配置保存时生成新的停用版本，原启用配置保持不变。
- 复制配置：直接进入新增页并带入被复制配置的业务主题提示词、校验字段和字段特殊要求。
- 唯一启用：同一业务主题必须且只能有一条启用配置；启用其他配置时自动停用原配置。
- 删除配置：仅停用配置可删除；原型中模拟为从列表隐藏。
- 系统提示词维护：独立页面按系统级章节维护全局提示词，保存时生成新的系统版本。

### 1.3 V1 状态与规则

- 配置状态只保留 `启用`、`停用`。
- 当前启用配置始终置顶，其他停用配置按更新时间倒序排列。
- 当前启用配置不提供独立停用操作，也不允许删除。
- 新增配置在已有启用配置时保存为停用；业务主题没有任何配置时，首条配置校验通过后保存并直接启用。
- 启用前只做配置完整性和字段有效性校验，不代表完成提示词效果评测。
- V1 使用本地 mock 数据，不实现后端接口、数据库、权限、真实版本计算和生产级校验。

## 2. 内容规划

### 2.1 信息架构

```text
V1 提示词配置
├── 系统功能菜单
│   ├── 提示词配置
│   └── 系统提示词
├── 提示词业务分类树
└── 当前业务主题
    ├── 业务主题名称 + 当前启用版本 + 新增配置
    ├── 配置列表
    └── 新增 / 编辑 / 详情
        ├── 基本信息：变更说明
        ├── 系统通用提示词版本与维护入口
        ├── 两列规则工作区
        │   ├── 业务主题提示词章节编辑 / 完整预览
        │   └── 参与校验字段 / 当前字段要求
        └── 详情追溯信息
└── 系统提示词维护
    ├── 版本与变更说明
    ├── 系统规则章节
    └── 当前章节编辑
```

### 2.2 列表页内容

- 页面顶部不设置状态页签。
- 不设置版本搜索、复杂筛选、查询方案和分页。
- 不展示录入/审核阶段、草稿数量、系统基础版本横幅、规则数量等信息。
- 列表顶部严格复用案例库两行结构：第一行为标准工具栏，左侧只放 `新增`；第二行为 32px 弱提示行，展示业务主题名称和当前启用版本。不新增自定义大标题栏。
- 列表字段固定为：
  1. 版本号；
  2. 更新时间；
  3. 更新人；
  4. 变更说明；
  5. 启停状态；
  6. 操作。
- 操作列全部平铺：停用配置展示 `详情 / 编辑 / 复制 / 删除 / 启用`，启用配置展示 `详情 / 编辑 / 复制 / 当前启用`。

### 2.3 新增、编辑、详情页内容

- 表单页头严格复用案例库标准结构：32px 圆形返回按钮 + `提示词配置 / 新增（编辑、详情）` 标题 + 右侧操作。
- 业务主题、版本号、来源版本移入“基本信息”正文中的单行弱摘要；详情页增加系统提示词版本。
- 基本信息只保留 `变更说明`，不使用多个禁用输入框展示系统自动信息。
- 系统通用提示词展示当前关联版本、系统统一处理范围、`查看说明` 和 `维护系统提示词` 入口。
- 业务主题提示词使用章节页签和大文本编辑区，预置六段模板：
  - 业务校验重点；
  - 特殊一致性要求；
  - 特殊合规性要求；
  - 佐证材料要求；
  - 政策适用与优先级；
  - 需人工复核的情形。
- 提供 `完整预览`，按六段标题自动拼装为可阅读的完整业务 Prompt。
- 参与校验字段使用正向勾选；显示字段名称和所属表单/分组。
- 系统固定排除字段不可勾选，并标注 `系统不参与校验`。
- 字段列表使用 32px 紧凑行并限制内部滚动高度，避免字段数量增加后挤占业务提示词编辑空间。
- 仅在右侧下方维护当前选中字段，按 `业务含义 / 比较口径 / 合规要求 / 材料要求 / 人工复核` 五类填写，不在列表逐行展开。

### 2.4 系统提示词维护

- 系统提示词为独立功能页，不在具体业务主题配置中直接编辑。
- 按八个系统级章节维护：角色与任务边界、固定结论与分类、运行时输入协议、优先级与冲突处理、通用校验流程、金额日期等专项规则、聚合与输出结构、安全约束与输出自检。
- 保存时必须填写变更说明并生成新版本；原型中模拟新版本号和当前启用状态，不实现真实发布、回滚和权限。
- 业务主题配置保留关联系统版本用于追溯；系统规则不能被业务规则覆盖。

### 2.5 数据字段

- `categoryId`：二级业务主题标识。
- `version`：系统自动生成的版本号。
- `status`：启用或停用。
- `changeNote`：变更说明。
- `businessSections`：六类业务主题提示词章节。
- `fields`：字段名称、分组、是否参与、是否系统锁定，以及五类字段要求。
- `sourceVersion`：新增或复制配置的来源版本。
- `systemVersion`：详情追溯用系统通用提示词版本。
- `updatedBy / updatedAt / enabledBy / enabledAt`：更新和启用追溯信息。

### 2.6 与已拼装 Prompt 的对应关系

页面保存后由系统自动生成与已拼装 Prompt 输入结构一致的 `businessRules`，业务人员不查看、不编辑 JSON：

```json
{
  "ruleVersion": "V1.3",
  "systemPromptVersion": "SYS-2.3",
  "excludedFields": [
    {
      "fieldKey": "remark",
      "fieldName": "备注",
      "reason": "当前业务配置未选择参与校验"
    }
  ],
  "validationFocus": "本业务主题重点核验事项",
  "fieldDefinitions": [
    {
      "fieldKey": "temporary-amount",
      "fieldName": "暂付款金额",
      "groupName": "资金信息",
      "definition": "当前事项形成的原始财政暂付款金额"
    }
  ],
  "consistencyRules": [
    {
      "scope": "field",
      "fieldKey": "temporary-amount",
      "fieldName": "暂付款金额",
      "requirement": "与同一事项、同一资金口径的材料金额比较"
    }
  ],
  "complianceRules": [],
  "evidenceRequirements": [],
  "policyApplicabilityRules": [],
  "manualReviewRules": []
}
```

- `ruleVersion`：取当前业务配置版本，对应已拼装 Prompt 输出中的 `businessRuleVersion`。
- `systemPromptVersion`：记录该配置关联的系统提示词版本。
- `excludedFields`：由未勾选字段和系统固定排除字段自动生成；优先使用动态表单稳定字段标识。
- `validationFocus`：取“业务校验重点”章节。
- `fieldDefinitions`：取已选字段的“业务含义”。
- `consistencyRules / complianceRules / evidenceRequirements / manualReviewRules`：分别组合业务章节要求和字段级同类要求，并通过 `scope` 区分业务级或字段级。
- `policyApplicabilityRules`：取“政策适用与优先级”章节。
- 表单字段定义由动态表单元数据提供，页面不要求业务人员填写字段编码或技术定义。
- `ledgerData / evidenceMaterials / policyFiles / auditContext` 属于每次运行时输入，不在提示词配置页面维护。
- 系统通用 Prompt 继续负责固定结论、异常分类、规则优先级、通用处理流程、金额日期等通用规则、结果聚合、输出 JSON 和自检要求。

### 2.7 版本口径

- `V1.3`：业务提示词配置版本，即 `businessRules.ruleVersion`。
- `SYS-2.3`：系统通用 Prompt 版本，详情页只读追溯。
- 已拼装 Prompt 输出中的 `promptVersion` 应由系统通用 Prompt 版本统一映射，不与业务配置版本混用；当前文档标题 V1.0 与输出固定值 `v0.3` 的差异需要在后续 Prompt 文档中统一。

## 3. 布局与结构

### 3.1 桌面端

- 主验收口径：`1920 × 1080`，浏览器缩放 `100%`。
- 顶栏复用项目 `TopBar`，高度 64px。
- 页面内容最大宽度 1920px，居中；页面外边距 16px。
- 列表页三栏结构：系统菜单 272px / 64px、业务树 310px / 18px、配置列表自适应。
- 列表工具栏 56px、弱提示行 32px、表格表头及数据行 32px；新增、编辑、详情页头固定 64px，不使用自定义大标题栏或卡片式摘要。
- 控件高度 32px，按钮与表格字号 14px，表单正文 13px，控件圆角 4px。
- 表格内容不足时不使用分页。
- 新增、编辑、详情页保留系统菜单，右侧使用独立全宽表单。
- 表单基本信息与系统提示词摘要保持全宽；核心规则区域采用两列布局，左侧业务主题提示词约占 `64%`，右侧参与字段约占 `36%`，列间距 16px。
- 左侧提示词编辑区最小高度 560px；右侧字段列表内部滚动，当前字段要求固定在列表下方，避免整页随字段数量无限增长。
- 系统提示词维护页使用 `260px 章节导航 + 自适应编辑区`。

### 3.2 响应式

- `821–1199px`：业务树收窄至 276px；规则工作区改为上下排列，保证提示词编辑宽度。
- `≤820px`：系统菜单、业务树和工作区纵向排列；业务章节页签三列换行，系统提示词章节导航改为两列。

- 系统菜单标题为 `提示词管理`，副标题为 `智能校验配置`；保留 `提示词配置` 与新增的 `系统提示词` 两项。菜单行、图标槽、选中态与案例库一致。
- 业务树使用案例库标准 32px 行高、14px 搜索框字号和标准搜索区边距；保持白底、浅分隔线和低饱和蓝灰选中态，折叠按钮固定在树表分隔线上。
- 表格沿用蓝色表头、浅灰网格、32px 表头与数据行。
- 表单页复用 `ufsp-form-head / ufsp-form-title / ufsp-form-actions`；正文使用蓝色竖线分节标题。
- 页面底色使用 `#F8FAFC`；系统菜单保留标准轻阴影，右侧业务工作区不额外增加卡片阴影。不使用厚边框、强阴影、过大圆角或大字号。
- 输入框、文本域不使用浏览器原生蓝色粗 outline；聚焦态为弱蓝色阴影。

### 4.3 组件状态

- 默认：白底、浅边界，正文 13px，标题 15–18px。
- 悬停：浅蓝灰背景或蓝色文字，不改变布局尺寸。
- 聚焦：按钮和录入控件使用弱蓝色阴影。
- 选中：业务树低饱和蓝灰底 + 深蓝文字。
- 禁用：系统排除字段灰底、灰字、不可操作。
- 空状态：提示当前主题暂无配置，并提供 `新增`。

## 5. 交互说明

- 选择业务主题后返回列表并更新当前启用版本。
- 点击 `新增` 直接进入新增页；已有启用配置时默认复制当前启用内容作为填写基础。
- 点击 `复制` 直接进入新增页，并带入被复制记录的全部配置。
- 点击 `启用` 弹出确认：“启用该配置后，当前启用的 Vx.x 将自动停用。”
- 点击编辑启用配置时，页内提示保存将生成新版本；主按钮为 `保存为新版本`。
- 点击业务提示词章节页签切换当前大文本编辑区；点击 `完整预览` 查看六段自动拼装结果。
- 点击字段行切换当前字段，字段勾选状态和五类字段要求分别维护；不再按列表行展开文本框。
- 点击 `维护系统提示词` 或系统菜单进入独立系统提示词页面；保存生成新的系统版本号。
- 系统通用提示词说明使用右侧只读抽屉，不展示完整 Prompt 或技术 JSON。
- 抽屉只做业务化概括，覆盖任务边界、固定结论、运行时输入、规则优先级、通用流程、结果聚合和输出自检。
- 页面运行规则通过 `business_rules` 变量提供给原型宿主，用于验证页面配置与已拼装 Prompt 输入结构的对应关系。
