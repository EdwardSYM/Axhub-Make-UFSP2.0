# 考核评价

## 1. 业务与功能

### 1.1 核心目标

本页面用于“针对中间表考核打分和数据校验”。用户在基础表中录入各处室、各指标的数据值后，点击保存直接进入校验页；系统对比用户录入的中间表数据值与套表统计值，展示是否一致、差异值和异常项。

页面只做前端静态演示：使用页面内本地 mock 数据，不接入后台接口、权限、数据库、真实业务公式或真实 AI 能力。

### 1.2 功能清单

- **基础表填报**：参考用户截图中的横向矩阵表，左侧展示业务类别和处室，横向展示多个考核指标字段，支持直接输入数据值。
- **标准业务框架**：复用问题库 AI 改造页面的 `ufsp-*` 框架方向，采用浅蓝业务画布、可收起功能侧栏、白色业务面板、48px 页签、56px 工具栏和 32px 表格行。
- **保存后校验**：点击“保存”后直接进入全页面数据一致性校验页，不走异步校验状态。
- **刷新数据**：校验页初始展示“等待刷新数据”，套表统计值为空；点击“刷新数据”后展示套表统计值和比对结果。
- **平铺式数值对比**：不使用左侧列表 + 右侧详情结构，而是沿用问题库校验页的结论卡和明细卡语言，按“处室 + 指标”平铺展示中间表填报值、套表统计值、差异和一致性结果。
- **异常识别**：对不一致项展示红色浅底行和“不一致”结果。

### 1.3 交互要点

- 点击左侧页面内“考核信息补充”：跳转到 `prototypes/evaluation-info-supplement`。
- 在基础表单元格输入：更新当前页面本地 mock 数据。
- 点击“保存”：直接进入数据一致性校验页，并将套表统计值置为待刷新状态。
- 点击“刷新数据”：展示静态套表统计值，并计算每个“处室 + 指标”的一致性结果。
- 点击返回：回到基础表填报页，保留已输入的中间表值。
- 点击“提交”：当前阶段保留页面级入口样式，不接入真实流转。

## 2. 内容规划

### 2.1 信息架构

```text
考核评价
├── 顶部全局导航（复用 TopBar）
├── 左侧考评库功能菜单
│   ├── 考核信息补充
│   └── 考核评价
└── 填报模式
    ├── 页面标题与保存按钮
    ├── 状态页签（基本信息 / 基础表填报 / 未完成 / 已完成）
    ├── 年度目录
    └── 基础表填报矩阵
└── 校验模式
    ├── 左侧考评库功能菜单
    └── 校验业务面板
        ├── 顶部标题操作栏
        ├── 校验报告摘要（问题库同款结论卡）
        └── 平铺式数值对比列表
```

### 2.2 数据来源

- **数据类型**：处室、业务类别、考核指标、配置字段、中间表填报值、套表统计值、差异值和校验结果。
- **数据源**：页面内本地 mock 数据。
- **关键字段**：
  - `office`：处室名称。
  - `category`：业务类别。
  - `metricName`：考核指标名称。
  - `field`：配置字段。
  - `inputValue`：用户录入的中间表数据值。
  - `statValue`：刷新后带入的套表统计值。
  - `diff`：中间表填报值与套表统计值的差异。
  - `matched`：是否一致。

## 3. 布局与结构

- **填报页布局**：顶部导航 + 浅蓝业务画布 + 标准功能侧栏 + 右侧白色业务面板；业务面板内部为跨栏状态页签、左侧年度目录和右侧矩阵表，矩阵表横向滚动承接多指标字段。
- **矩阵表**：左侧固定语义为业务类别、处室；表头分三层展示指标组、考评要点和配置字段，数据单元格为可输入控件。
- **校验页布局**：与问题库校验页一致，TopBar 下方先进入浅蓝业务画布；第一列为考评库功能菜单，菜单右侧为全页面白底校验业务面板；面板内顶部 64px 标题操作栏，报告摘要在上，数值比对明细卡在下。
- **平铺比对**：每行展示“处室 · 指标”、业务类别/评分标准、中间表填报值、套表统计值、差异和结果；异常项使用浅红底和红色结果强调。

## 4. 视觉规范

- 遵循 `/src/docs/业务页面设计规范.md`、问题库 AI 改造框架和用户截图中的基础表填报密度；按钮、页签、工具栏、分页和校验页头部按问题库 `ufsp-*` 组件标准收敛。
- 使用低饱和蓝色表头和白色录入单元格，输入框不额外加重边框，保持表格化填报效率。
- 校验页不使用左侧列表右侧详情；保留问题库结论卡的左侧状态线、统计块和明细卡头部，用浅底行面和状态色区分一致/不一致，更适合单纯数值对比。
- 刷新前套表统计值显示“待刷新”，避免误解为已经完成比对。
