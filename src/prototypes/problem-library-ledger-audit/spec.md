# 工作台账审核

## 1. 业务与功能

### 1.1 核心目标

本页面作为问题库（AI改造）下的独立原型入口，用于单独展示“专项问题整改 / 台账分发录入 / 工作台账审核”的待审核列表与审核校验工作区。

页面只做前端静态演示：使用本地 mock 数据，不接入后台接口、权限、数据库、真实业务公式或真实 AI 校验能力。

### 1.2 功能清单

- **独立页面入口**：页面树中单独显示“工作台账审核”，打开后默认进入审核列表，不需要依赖“工作台账录入与审核”页面内的功能切换。
- **工作台账审核列表**：展示待审核、已审核、全部页签，左侧年度/主题树，工具栏，紧凑台账表格和居中分页。
- **审核入口与结果动作分离**：列表顶部“审核”只负责选择单条或多条数据进入审核校验；审核校验页顶部再拆分为“通过 / 退回”。
- **审核校验工作区**：沿用录入校验页的同一套输出口径，按当前台账、佐证材料和制度依据统一校验，并按“一致性 / 合规性”两类问题类型展示“全部一致 / 存在异常”结论和“建议通过 / 建议退回”。
- **状态口径**：“全部一致”表示当前数据未发现一致性或合规性异常；“存在异常”包括一致性问题、合规性问题、资料支撑不足或无法判断等需要人工复核的数据。

### 1.3 交互要点

- 点击页面树“工作台账审核”：进入独立审核页面，默认选中内部功能菜单中的“工作台账审核”。
- 勾选表格行：选择单条或多条待审核台账，列表顶部“审核”按钮按当前勾选范围进入审核校验。
- 点击行内“审核”：以单条数据进入审核校验。
- 审核校验页顶部操作：左侧返回列表；右侧只放“推理过程 / 通过 / 退回”。
- 进入审核校验页后直接查看随流程带入的智能校验结果，不在审核岗提供重新校验动作。
- 点击“推理过程”：打开右侧抽屉查看当前台账、佐证材料、制度依据的统一校验过程，以及一致性 / 合规性问题归类。
- 点击“通过”：若勾选范围全部一致则直接通过；若存在异常，只打开风险确认，提示建议查看异常明细或补充审核说明，未填写也可确认通过。
- 点击“退回”：不再打开逐条填写弹窗，直接按当前勾选范围退回；若某条数据已填写审核说明则作为退回留痕，否则使用系统异常摘要。
- 点击当前数据级“不认可说明”：在“审核异常明细”标题区显示入口；右侧抽屉只读展示录入岗对 AI 异常的标记、说明和证明截图。
- 点击当前数据级“审核说明”：在“审核异常明细”标题区显示入口；右侧抽屉先只读展示历史审核岗说明和截图，再记录当前审核岗选填审核说明和证明截图；后续多级审核按岗位累计追加。

## 2. 内容规划

### 2.1 信息架构

```text
工作台账审核
├── 顶部全局导航（复用 TopBar）
├── 左侧功能菜单（默认选中工作台账审核）
└── 右侧业务内容区
    ├── 工作台账审核列表
    │   ├── 状态页签（待审核 / 已审核 / 全部）
    │   ├── 可收起年度/主题树
    │   ├── 工具栏（审核 / 废除 / 销号 / 导出 / 查询）
    │   ├── 台账审核表格
    │   └── 居中简版分页
    └── 审核校验工作区
        ├── 顶部标题操作栏
        ├── 本次审核数据筛选和勾选列表
        ├── 审核校验结论
        ├── 审核异常明细
        ├── 审核推理抽屉
        ├── 审核说明抽屉
        └── 审核通过风险确认弹窗
```

### 2.2 数据来源

- **数据类型**：台账审核列表、统一智能校验结果、异常事实、不认可说明、审核说明和审核建议。
- **数据源**：页面内本地 mock 数据。
- **关键字段**：
  - `previousAiStatus`：列表历史留痕中的录入岗提交状态，仅用于说明录入岗是否曾在异常情况下继续提交，不作为审核页主校验口径。
  - `reviewRequirement`：本条数据对照制度依据和材料口径的静态结果。
  - `dataStatus`：审核页统一状态，取值为“全部一致 / 存在异常”。
  - `reviewStandard`：审核标准或制度要求文本。
  - `suggestion`：系统给出的审核通过或退回建议。
- `previousSubmitProofs`：录入岗在“存在异常仍提交”时补充的不认可说明和证明截图。
- `submitterRejectMark`：录入岗是否对单条 AI 判断标记不认可，取值为“录入岗已标记不认可 / 录入岗未标记不认可”，仅供审核参考。
- `auditReviewNote`：审核岗对当前数据级异常的审核说明和证明截图，按岗位累计，均不强制填写。

审核默认示例应覆盖多种状态：合规性问题、一致性问题、录入岗已标记不认可、录入岗未标记不认可，避免只展示单一数据状态。

## 3. 布局与结构

- **布局模式**：顶部导航 + 左侧功能菜单 + 右侧审核业务区。
- **列表区**：沿用业务列表页 32px 控件、32px 表格行、4px 控件圆角、浅色分隔和居中分页。
- **审核校验区**：沿用录入校验页的两栏结构，左侧约 `330px` 放本次审核数据筛选和项目列表，右侧展示审核结论、项目上下文、三项统计和异常事实；结论区统计统一为“异常事实 / 合规性问题 / 一致性问题”。
- **桌面优先**：优先保证 1440px 以上宽屏展示；窄屏保留横向滚动。

## 4. 视觉规范

- 遵循 `/src/docs/业务页面设计规范.md` 和“AI 佐证一致性校验页 / 审核校验页”补充规则。
- 左侧功能菜单继承问题库功能列表页的 iconfont 下载 SVG 原件规范：图标文件由 `src/prototypes/problem-library-function-list/icons/` 统一维护，代码只做 XML 清洗、统一容器、光学比例校准和 `currentColor` 状态适配；审核节点使用 iconfont “校验”图标，展开态统一 `30px` 图标容器，折叠态统一 `32px` 图标容器，选中态使用顶栏同源的低饱和蓝灰行面、深蓝文字和半透明深蓝图标底。
- 列表顶部只保留进入校验的“审核”；审核校验页顶部拆分“通过 / 退回”，其中“通过”在全部一致时直接完成，存在异常时只进入风险确认，“退回”直接流转。
- 不认可说明和审核说明拆成两个当前数据级入口：不认可说明只读展示录入岗态度、说明和截图；审核说明上半部分只读展示前序审核岗累计说明，下半部分填写当前审核岗说明和截图。批量通过或退回不要求逐条填写说明后才能流转。
- 结论区先回答“是否全部一致”，宽屏下沿用录入校验页统计布局，展示“异常事实 / 合规性问题 / 一致性问题”，不再解释历史一致性和审核标准两段结果。
- 审核建议不做成右侧大块统计，不重复展示“退回”；建议通过或退回只在结论描述中表达。
- 左侧筛选只使用“全部数据 / 全部一致 / 存在异常”，避免重复状态说明。
- 审核异常明细按“一致性 / 合规性”问题类型组织，并展示“录入原文 / 佐证附件或审核依据 / 判断原因”；审核建议只在结论描述中表达，不在每条事实里重复展示。事实行同步展示录入岗是否标记不认可，不展示“无异常 / 已递交说明 / 未递交说明”等说明状态，不放“查看依据 / 填写意见 / 审核建议”。“不认可说明 / 审核说明”作为当前数据级入口放在明细标题区，跟随左侧当前选中数据展示。
- 使用白色整体底、浅底分组、行分隔、文字层级和状态色表达层级，不使用卡片套卡片、重边框或内阴影堆叠。
