# 全局分析 - 主题分析规格文档

## 1. 页面定位

主题分析用于回答“哪些监督主题风险突出、某个主题下哪些主体表现较差、风险由评价/监控/整改哪些因素构成”。本页承接全局总览和主体分析中的主题点击，不承担业务办理。

## 2. 功能清单

- 顶部导航：复用公共 `TopBar`，全局分析菜单仅保留全局总览、主体分析、主题分析。
- 筛选区：统计期、管理范围、监督体系、分析口径。
- 当前上下文：显示当前范围、周期、体系和锁定主题。
- 主题风险摘要：高风险主题、问题总量、超期整改、规则命中。
- 主题风险卡片：展示主题名称、体系、风险、评价均分、问题数、低分主体、数据状态。
- 主题画像：展示当前主题的均分、风险等级、问题、规则命中、低分主体、整改完成率。
- 主题下主体表现：展示当前主题下风险较高的主体排名。
- 主题-主体热力图：行是主体，列是主题，单元格展示得分与问题数。
- 主题趋势：展示问题数、规则命中、整改完成率、评价均分变化。
- 智能研判：围绕当前主题给出风险集中对象和建议动作。

## 3. 交互规则

- 点击主题卡片：锁定主题并刷新主题画像、主体排名和研判。
- 点击主体排名：跳转主体分析并带入当前主题。
- 点击热力图主题列：锁定主题。
- 点击热力图单元格：进入主体分析并带入当前主题和主体。
- 从全局总览或主体分析带入 `theme` 查询参数时，默认锁定该主题。

## 4. 视觉规范

- 延续全局总览的蓝白浅渐变、无边框软分区和高密度信息组织。
- 主题卡片强调“主题名称 + 风险 + 数据状态”，避免堆砌图表。
- 风险语义使用红、橙、绿；数据状态使用蓝、橙、紫。
- 与主体分析保持结构相似，但信息视角从“谁”转为“管哪里”。

## 5. 验收要点

- `index.tsx` 和 `spec.md` 同步存在。
- 页面不再出现“页面内容待补充”。
- 主题点击、主体跳转可用。
- `node scripts/check-app-ready.mjs /prototypes/theme-analysis` 验收通过。
