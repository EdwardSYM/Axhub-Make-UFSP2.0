# 湖南问题库演示原型规格

## 1. 页面定位

本原型用于湖南财会监督一期“问题入口 + 结果归集”演示，目标是先让不同来源的问题进得来、沉得下、查得到，再考虑线上分发和整改流转。

本期只建设“问题归集登记”和“问题查询管理”两个菜单。问题归集登记承担问题登记与整改结果登记，问题查询管理承担按区划和统一字段查询；暂不建设表单配置后台，不接入真实接口、数据库、权限或线上办理流程。

## 2. 功能范围

### 2.1 问题归集登记

- 支持巡视、审计、专项检查、日常监督、外部移交和其他来源的问题统一归集。
- 支持批量导入和人工录入。
- 模块内设置“问题登记”“未回录结果”“已回录结果”三个页签：问题登记展示全量问题，后两个页签分别承接尚未登记整改结果和已登记整改结果的数据。
- 登记侧按当前用户可见区划和预置来源模板展示字段；演示中固定显示当前区划，不提供跨区划选择。
- 批量导入页展示来源模板、文件选择、原始数据预览以及缺失、格式和重复提示，不展示字段映射结论。
- 信息补充页同时展示原始导入数据、系统通用字段和来源扩展字段，支持核对、补充和保存登记。
- 整改结果登记支持检索已登记问题，回录整改情况、整改措施、完成时间、整改材料、销号结论、销号时间和销号材料。
- 归集登记保存后直接形成统一问题台账，不设置待确认、入库、不入库等审批式状态，也不建设问题分发、任务下发或审批流程。

### 2.2 问题查询管理

- 统一查询已经归集保存的问题存量数据。
- 支持按所属区划、问题来源、年度、问题类型、责任单位和整改状态筛选。
- 列表固定展示统一标准字段，不在表头中追加不同来源的扩展字段。
- 支持查询方案、列设置和导出演示。
- 问题详情展示标准问题信息、原始表单数据、整改结果和更新记录；原始表单数据保留来源模板的原字段、原值和原始文件入口。
- 查询管理只负责查询和查看，不提供问题登记或整改结果录入操作。

## 3. 信息架构

```text
湖南问题库
├── 公共 TopBar
├── 问题库功能菜单
│   ├── 问题归集登记
│   └── 问题查询管理
└── 当前模块展示区
    ├── 问题登记（全量） → 批量导入预览 / 人工录入 / 信息补充
    ├── 未回录结果 → 整改与销号结果登记
    ├── 已回录结果 → 整改与销号结果查看更新
    └── 查询列表 → 问题详情 → 标准信息 / 原始表单数据 / 整改结果 / 更新记录
```

表单配置作为后续扩展模块预留，不在本期菜单中展示。

## 4. 预置动态模板

| 问题来源 | 通用字段之外的演示字段 |
| --- | --- |
| 巡视移交 | 巡视批次、巡视组、移交日期 |
| 审计移交 | 审计项目、审计文号、审计年度 |
| 专项检查 | 专项名称、检查项目、检查期间 |
| 日常监督 | 监督主题、发现渠道、监控规则 |
| 外部移交 | 移交单位、移交文号、移交日期 |

所有模板都共享问题标题、问题来源、责任单位、问题类型、问题事实、涉及金额、发现时间和附件等通用字段。

## 5. 关键页面

### 5.1 问题归集列表

- 顶部页签为“问题登记”“未回录结果”和“已回录结果”。
- 三个页签统一采用“左侧来源目录 + 右侧单行工具栏和标准表格”的同构骨架，只切换数据范围和行级主操作，避免用户在同一登记任务内反复学习布局。
- “问题登记”展示全量问题，主要操作为批量导入、人工录入和导出，行级只保留“查看编辑”。
- “未回录结果”只展示未登记整改结果的问题，行级主操作为“登记结果”；“已回录结果”展示已回录或已销号问题，行级主操作为“查看更新”。
- 列表不设置勾选、批量入库或审批式数据状态；不在列表上方重复显示当前区划、来源模板或页面说明。
- 标准表格按业务信息量固定列宽：标题、编号和责任单位获得主要宽度，来源、区划、类型、状态和单一操作保持紧凑，长文本省略并通过悬停查看完整值。

### 5.2 批量导入预览

- 64px 全页面操作页头。
- 顶部选择问题来源、对应模板和导入文件。
- 下方显示原始导入数据预览和待补充、疑似重复提示，不展示映射字段数量或映射结果。
- 异常直接定位到数据行，支持返回调整并继续补充登记信息。

### 5.3 信息补充 / 人工录入

- 左侧展示来源材料或导入原始数据，右侧展示通用字段和来源扩展字段。
- 字段按“问题基础信息、来源扩展信息、材料附件”分组。
- 人工录入使用连续白色工作面和四列表单栅格；导入后信息补充只将左侧原始数据作为独立核验载体，右侧主录入区保持连续表单，不按章节拆分卡片。
- 人工录入和导入后信息补充复用同一表单结构；人工录入不显示原始导入值。

### 5.4 整改结果登记

- 在问题归集登记模块内分别通过“未回录结果”和“已回录结果”页签管理，两个页签与全量问题登记页共用来源目录、工具栏和表格结构。
- 未回录问题通过“登记结果”进入连续白底的整改结果登记表单；已回录问题通过“查看更新”进入同一表单查看或补充最终结果。

### 5.5 问题查询列表与详情

- 查询列表使用固定标准表头：问题标题、问题编号、所属区划、问题来源、责任单位、问题类型、整改状态和操作。
- 查询列表左侧使用所属区划树，右侧只保留一行标准工具栏和表格；来源、类型、年度等条件由标准筛选入口承载，不再另起一行平铺筛选控件。
- 详情页通过页签查看标准问题信息、原始表单数据、整改结果和更新记录。
- 原始表单数据按来源模板原字段展示，并保留原始文件和导入批次入口；当前阶段不展示字段映射关系、映射数量或遗漏提示。
- 查询管理不提供整改回录按钮。
- 整改结果登记使用连续白底全页面表单，以分节标题、间距和弱分隔组织最终结果、佐证材料和销号信息，不增加摘要卡或章节卡片。
- 不展示分发路径、整改进度时间轴、督办、审核、退回或线上销号审批。

## 6. 数据与交互

- 数据全部为页面内本地 mock 数据。
- 左侧功能菜单支持展开和收起，并通过 `feature` 查询参数记录当前模块。
- 登记来源选择会切换预置模板和表单来源字段；查询列表表头保持固定。
- 导入、保存登记、回录、销号和导出只提供演示反馈。
- Axure 变量暴露当前 `feature_key` 和 `feature_name`。

## 7. 布局与视觉

- 复用公共 `TopBar`、案例库左侧功能菜单、标准页签、业务树、单行工具栏、表格、分页、表单页头和表单控件。
- 页面采用“TopBar → 问题库功能菜单 → 业务区”的结构；业务区有来源目录时继续为“来源目录 → 列表”。
- 独立业务面板和业务卡片统一 `8px` 圆角，控件使用 `4px` 圆角；全页面表单章节不是独立卡片，不应用面板圆角。
- 遵循无边框优先，通过白色工作面、浅底分组、文字层级和必要分隔组织信息。
- 列表页面不增加“当前区划 / 登记来源 / 使用模板”、查询口径或功能说明等重复提示；当前位置由功能菜单、页签和左侧业务树共同表达。

## 8. 暂不处理

- 表单模板配置后台及模板版本管理。
- 真实 Excel 解析、字段映射和数据校验。
- 问题自动去重、智能分类或标签算法。
- 问题分发、转办、整改任务下发、进度填报、督办和逾期提醒。
- 整改审核、退回、线上销号审批和统计看板。
